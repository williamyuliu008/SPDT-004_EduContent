## 零、战略定位：视觉管线是内容生产的核心动脉

> **核心洞察**：人眼是人类获取信息的主要渠道。内容管线若缺乏视觉开发能力，教学内容的"到达率"和"留存率"将大打折扣。本轮探索与另一窗口「AI制图」（0721-AI制图）共同构成了完整的**双轨视觉管线**。

### 视觉管线的两条分支

```
内容需求
    │
    ├─── A. AI配图（PT-039 · 探索窗口）
    │         ├── AI生图：image_synthesize 生成场景图、人物图、历史情境图
    │         └── AI选图：从海量图库中筛选适合的高质量图片
    │         → 适用场景：叙事性内容（历史场景、书法碑帖、文学情境）
    │         → 产出形态：PNG/JPG（像素图）
    │
    └─── B. AI制图（0721-AI制图 · 另一探索窗口）
              ├── 结构化图表：LLM生成 Mermaid/PlantUML 代码 → 渲染为图
              ├── 原理示意：电路图、流程图、架构框图、时序图
              └── 知识图谱：概念关系图、知识网络图
              → 适用场景：逻辑性内容（技术原理、流程步骤、因果关系）
              → 产出形态：SVG/HTML（矢量图，可无限缩放）
```

### 两条分支的互补逻辑

| 维度 | AI配图（像素图） | AI制图（矢量图） |
|:---|:---|:---|
| **信息类型** | 叙事性、情境性、感性内容 | 逻辑性、结构性、理性内容 |
| **表达方式** | 视觉场景（"看起来是什么样的"） | 抽象结构（"是如何运作的"） |
| **典型应用** | 商鞅变法历史场景、小篆书法碑帖 | 科举流程图、考点知识网络、电路原理图 |
| **AI能力依赖** | 图像生成模型 + 图库筛选 | LLM代码生成 + Mermaid渲染器 |
| **内容审核难点** | 风格一致性、历史准确性 | 逻辑完整性、命名规范性 |
| **两者如何协同** | "商鞅南门立木的场景图" + "变法流程步骤图" 共同服务于同一知识单元 | |

### 为什么这对考点知识库体系至关重要

教学内容的核心挑战不是"信息量不足"，而是**"信息无法有效到达"**。

视觉是信息到达率最高的人类感知通道——人类大脑处理图像的速度是文字的 6万倍，视觉信息留存率比纯文字高 65%（MIT 神经科学研究）。一套面向备考场景的内容体系，如果缺乏高质量视觉内容，等于主动放弃了最高效的信息传递方式。

**双轨视觉管线的战略价值：**
- AI配图解决"生动性"：让历史场景"活起来"，让书法碑帖"可见可感"
- AI制图解决"结构性"：让知识脉络清晰可追溯，让学习路径可视化
- 两者共同构成：叙事感 × 逻辑感 = 完整的认知体验

> **一个知识单元的理想呈现方式**（举例：商鞅变法）：
> 1. 历史叙事配图：南门立木的场景插图（AI配图 · 叙事层）
> 2. 变法流程图：求贤令→立木取信→刑及太子→书同文（AI制图 · 逻辑层）
> 3. 书法关联图：小篆字形示例（AI配图 · 跨学科层）
>
> 三者叠加 = 视觉、叙事、逻辑三位一体的备考体验

### 3.2 教训与反思

**教训1：规划文档更新滞后于执行**

执行中新增了「历史叙事配图」方向（不在原始规划内），但规划文档未及时修订，导致后续跟踪时无法对齐「已完成」与「计划中」的边界。**应该在每次方向调整时同步更新规划文档，或设置「规划文档变更日志」。**

**教训2：图源问题应在管线设计阶段解决**

Cards 04/05 的台北故宫/故宫图片需要手动下载，是**管线设计阶段的盲点**。书法本体库的「标准参照层」对图源质量要求极高，缺少高质量公开图源时，管线会卡在「人工介入」环节。

教训2的行动项：建立「书法图源地图」，标注每个书家的高质量免费图源（CC0/公共领域）及其下载方式，将图源准备纳入管线的前置步骤。

**教训3：手势调试轮次过多（6轮）**

滑动换图功能调试了6轮，根因是 `@State` 时序问题。这说明：
- 对于 HarmonyOS ArkUI 的「非常规用法」（手动 TouchEvent 而非官方 Gesture API），需要更早进行**原理性调研**（查 SDK 文档/Observable 行为），而不是盲目试错
- 教训：涉及 `@State` 响应式机制的核心行为，应先做小样本验证，再进全量实现

**教训4：阻尼感参数（0.70）的调整依赖用户反馈**

阻尼系数从 1.0 调到 0.70 是用户的直觉判断（"少了一点阻尼感"），而非量化依据。理想情况应有：
- 量化指标：滑动摩擦系数 vs 用户满意度的对应关系
- 快速A/B测试能力：不同参数一键切换
