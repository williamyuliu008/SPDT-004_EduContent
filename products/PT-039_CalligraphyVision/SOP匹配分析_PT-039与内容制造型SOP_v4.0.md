```

```

## 五、核心差异深度分析

### 5.1 范式差异：文档驱动 vs 领域本体驱动

**SOP v4.0的默认模式**：
```
领域本体（KBC）→ 术语词典 → CMC体裁注册 → 创作管线
```

**PT-039的实际模式**：
```
微剧本JSON → AI生图提示词 → image_synthesize → App rawfile
```

**判断**：这是两种不同的**内容制造范式**，各有其适用场景：

| 维度 | 本体驱动（SOP v4.0） | 文档驱动（PT-039） |
|:---|:---|:---|
| 适用内容 | 知识密集型文本（白皮书/报告） | 叙事性多模态内容（剧本/配图） |
| 知识组织 | 结构化本体（概念→关系） | 场景化文档（场景→情节→人物） |
| AI依赖 | 本体约束生成（低幻觉） | 文档约束生成（依赖prompt质量） |
| 质量控制 | 领域本体校验 | 人工肉眼审核 |
| 典型产出 | PT-038古代史长文 | 墨骨山河微剧本+AI配图 |

**建议**：SOP v4.0应增加"文档驱动模式"作为另一条合法路径，与"领域本体驱动"并列。不是PT-039"不符合SOP"，而是PT-039代表了一种SOP尚未覆盖的内容制造范式。

### 5.2 关键缺口：多模态内容的系统性缺失

SOP v4.0完全没有涉及：

**① 视觉内容的质量约束**
- AI配图：风格一致性、历史准确性、书法字形正确性
- AI制图：逻辑完整性、命名规范性、连接正确性
- 两条视觉管线都没有对应的"约束引擎"

**② 视觉反馈闭环**
- 像素图无法自检（SOP无定义）
- 人工审核的分层（可视化层 vs 语义逻辑层）——0721-AI制图窗口已识别这一挑战

**③ 多模态内容的M3.2知识源连通**
- AI配图的知识绑定：场景→历史考点评分（已有：HIS-AS-004/005/006）
- 但这只是手动绑定，SOP无多模态知识注入机制

### 5.3 跨学科体裁的发现机制缺失

"商鞅变法 × 小篆书同文"是一个**跨学科体裁**——历史考点 + 书法考点指向同一知识单元。SOP v4.0：
- M3.1体裁匹配只考虑"本领域内体裁"
- 无跨学科体裁发现机制（两个KBC域的交集识别）

### 5.4 分发层整合的缺失

SOP v4.0的M6交付止于"人类确认ContentSpec满足"，但PT-039的实际价值还包括：
- App rawfile → HAP → 设备运行
- Web Viewer部署（https://...mcode.cn）
- 用户使用数据（无感知，但存在）

**分发层整合**是"内容制造型→内容消费型"的关键一跳，SOP完全未覆盖。

## 六、协同改进方案

### 6.1 SOP v4.0 改进建议

#### A. 增加"视觉内容制造"模块（B5新分类）

在B1-B4之外，新增**B5 视觉叙事内容**：

```yaml
B5 视觉叙事内容:
  判据:
    C1: 最终产出包含像素图或矢量图（>30%视觉占比）
    C2: 视觉生成规则可通过prompt模板化
    C3: 视觉内容有领域准确性要求（历史/科学/书法等）
    C4: 视觉模板可跨知识域复用（如：历史叙事配图模板）
  自动化上限: 40-60%  # 人工审核比文本更高
  典型领域: 历史配图、书法碑帖、科学原理示意图、知识图谱可视化
  质量约束补充:
    - 可视化合规性（对齐/连接/比例）
    - 语义逻辑正确性（是否符合该领域知识）
    - 风格一致性（系列内视觉统一）
```

#### B. 增加"文档驱动模式"子流程（与M2并列）

```
M2a 领域本体驱动（原有，适用于B1-B4）
M2b 文档驱动（新增，适用于B5及跨学科体裁）
    M2b.1: 微剧本JSON解析 → 提取场景结构
    M2b.2: 场景 → 视觉生成提示词映射
    M2b.3: 生成参数模板化（分辨率/风格/尺寸比）
    M2b.4: 质量约束注入（历史准确性/书法字形）
    M2b.5: 输出：场景级VisualSpec（替代TextSpec）
```

#### C. 增加"多模态内容体裁"注册格式

