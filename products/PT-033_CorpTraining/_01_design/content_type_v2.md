# B-P3 产出 —— Content Type扩展到5种

> 日期：2026-07-03 | 目标：从3种扩展到5种（接近7±2目标区间）
> 新增：case_study（项目实战案例）+ tool_demo（工具操作演示）

---

## 一、新增类型1：`case_study` — 项目实战案例

**内容特征**：展示一个完整的实战项目——从需求到交付的完整流程，含背景、挑战、方案、结果、经验。

**最佳呈现形式**：因果链图（causal_chain）+ 步骤卡片（box_diagram）——项目时间线 + 关键决策点 + 成果展示。

**严禁使用的形式**：纯文字叙述（失去"项目流程感"）、无成果数据的案例。

**原有graphic_type映射**：
- `causal_chain`：项目阶段链（需求→设计→实施→验证→交付），≤6节点
- `box_diagram`：关键决策点 + 备选方案，≤6节点

**审计条件（7条）**：

| # | 审计条件 | 验证方式 | 级别 |
|---|---------|---------|------|
| E1 | 案例包含"背景→挑战→方案→结果→经验"五要素 | 结构化关键词检查 | BLOCK |
| E2 | 案例结果有量化数据——"提升了X%""节省了Y小时""减少了Z个错误" | 数字模式匹配 | BLOCK |
| E3 | 方案选择有对比——"为什么选A不选B"有解释 | 对比标记检查 | WARN |
| E4 | 经验可迁移——"这个案例给你什么启发"有明确总结 | 经验段存在性检查 | WARN |
| E5 | 案例真实性标注——是否为改编/虚构/真实案例 | 真实性标记检查 | WARN |
| E6 | 技术细节准确性——工具/API/版本号与当前一致 | 术语库比对 | BLOCK |
| E7 | 案例复杂度适合培训目标——深度控制在10-15分钟 | 节点数+文字量综合判定 | WARN |

**Schema扩展**：
```json
{
  "content_type": "case_study",
  "graphic_type": "causal_chain",
  "statement": "AI辅助竞品分析",
  "narration": "...",
  "case": {
    "background": "某电商公司的市场团队需要每周产出竞品分析报告，手工收集数据耗时8小时",
    "challenge": "数据来源分散（电商平台/社交媒体/行业报告），格式不统一，手工整理易出错",
    "solution": "用AI写作工具+数据分析工具搭建半自动管线",
    "result": "报告产出时间从8小时降到2小时，数据准确率从85%提升到98%",
    "lesson": "关键不是AI有多强，而是把AI嵌入到已有的工作流中——先定义'好的报告'长什么样，再让AI来填空"
  },
  "steps": [
    {"phase": "prepare", "label": "定义报告模板", "detail": "竞品报告需要哪些章节/指标"},
    {"phase": "execute", "label": "AI收集数据", "detail": "用ChatGPT分析竞品官网+社交媒体"},
    {"phase": "execute", "label": "AI生成报告", "detail": "将收集的数据填入模板"},
    {"phase": "verify", "label": "人工审核精修", "detail": "检查数据准确性，补充行业判断"},
    {"phase": "adjust", "label": "迭代优化模板", "detail": "根据每周反馈更新报告模板"}
  ]
}
```

## 二、新增类型2：`tool_demo` — 工具操作演示

**内容特征**：展示一个软件/工具的具体操作——屏幕上的点击、输入、配置，配以旁白解释每一步的目的。

**最佳呈现形式**：代码编辑器风格面板（box_diagram + 特殊样式）——模拟IDE/浏览器/终端界面，带行号和语法高亮。

**严禁使用的形式**：纯文字描述操作（看不到界面）、静态截图（缺乏操作流程感）。

**原有graphic_type映射**：
- `box_diagram`：操作步骤节点（代码编辑器风格），≤8节点
- `term_card`：界面元素标注（按钮/菜单/输入框名称）

**审计条件（7条）**：

| # | 审计条件 | 验证方式 | 级别 |
|---|---------|---------|------|
| D1 | 每步操作有"做什么+在哪里做+为什么这样做"三个要素 | 结构化检查 | BLOCK |
| D2 | 界面元素名称与实际工具一致——"File菜单"非"文件菜单"（如果工具是英文界面） | 术语库比对 | BLOCK |
| D3 | 有"操作前"和"操作后"的状态对比——让学员知道"做对了会看到什么" | 预期结果存在性 | WARN |
| D4 | 异常情况有覆盖——"如果这一步不成功，检查什么" | 异常处理存在性 | WARN |
| D5 | 步骤数≤8（含准备和验证步骤） | Schema校验 | BLOCK |
| D6 | 快捷键/快捷操作有标注——"也可以按Ctrl+Enter直接发送" | 快捷键标记检查 | INFO |
| D7 | 工具版本号标注——"本演示基于ChatGPT 2025年7月版本" | 版本标记检查 | WARN |

**Schema扩展**：
```json
{
  "content_type": "tool_demo",
  "graphic_type": "box_diagram",
  "statement": "ChatGPT写邮件",
  "narration": "...",
  "tool": {
    "name": "ChatGPT",
    "version": "2025.07",
    "platform": "Web"
  },
  "steps": [
    {"phase": "prepare", "label": "打开ChatGPT", "detail": "访问chat.openai.com，登录账号", "expect": "看到对话界面"},
    {"phase": "execute", "label": "输入需求", "detail": "在输入框中输入邮件需求描述", "shortcut": "Ctrl+Enter发送", "expect": "ChatGPT开始生成回复"},
    {"phase": "execute", "label": "优化Prompt", "detail": "追加：'语气正式一些''增加行动项'", "expect": "回复更接近需求"},
    {"phase": "verify", "label": "检查输出", "detail": "检查：关键信息齐全？语气合适？格式正确？", "expect": "可直接复制使用"},
    {"phase": "adjust", "label": "二次修改", "detail": "如果不对，继续对话调整", "error_handling": "如果ChatGPT说'无法理解'——用更简单的句式重写需求"}
  ]
}
```

## 三、5种Content Type完整谱系

| content_type | graphic_type | 审计条件数 | 覆盖率 | 适用场景 |
|-------------|-------------|----------|--------|---------|
| `concept` | term_card | 7（C1-C7） | ~25% | 工具概念、术语定义 |
| `steps` | box_diagram+四阶段 | 10（S0-S8'） | ~35% | 操作流程、使用方法 |
| `contrast` | comparison_table | 7（R1-R7） | ~15% | 工具对比、方案选择 |
| **`case_study`** 🆕 | causal_chain | **7（E1-E7）** | ~10% | 项目实战案例 |
| **`tool_demo`** 🆕 | box_diagram(IDE风格) | **7（D1-D7）** | ~10% | 工具操作演示 |

**5种类型总覆盖率：~95%**（对照AI_video_edu培训课程的Series A内容）。已达到7±2优化区间（5种，可扩展至7种）。

## 四、知识库流程验证（OMAS验证项）

新增类型的设计过程本身验证了OMAS的知识库构建流程：

| 构建步骤 | 操作 | 产出 |
|---------|------|------|
| 1. 内容分析 | 扫描AI_video_edu培训课程19节课，识别未覆盖的呈现模式 | `case_study`和`tool_demo`两种新模式 |
| 2. 结构定义 | 为每种模式定义"最佳形式+禁止形式+审计条件" | Schema+审计条件 |
| 3. graphic映射 | 判断现有graphic_type是否够用，是否需要扩展 | 两种都映射到现有类型，无需新建 |
| 4. 注入Prompt | 在T-01/T-03/T-04的content_type枚举中增加新类型 | Prompt更新 |
| 5. 验证 | 用现有培训素材测试新类型的分类准确率 | 待B-P4验证 |
