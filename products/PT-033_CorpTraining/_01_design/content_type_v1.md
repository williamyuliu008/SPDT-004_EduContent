# Day 2 产出 —— Content Type + 审计条件定义

> 日期：2026-07-03 | 基于：AI_video_edu 培训课程体系 v2.0 + CGM 五支柱
> 方法论：Spec-Audit同步定义——每种content_type在设计Schema的同时定义7±2条审计条件

## 一、Content Type 体系设计

基于AI_video_edu的岗位能力三阶模型（L1工具操作/L2项目落地/L3问题解决）和三种课程系列（A实战工具箱/B全景认知/C深度拆解），**CGM构造管线关注的是"呈现形式"层面的分类**——即每种培训内容以什么图形/布局/节奏呈现。这与"教学内容分类"（工具/数据/编程/知识管理）是正交维度。

### 1.1 三维正交分类框架

```
教学内容分类（业务层）         呈现形式分类（CGM管线层）           受众分层（编译层）
─────────────────────         ────────────────────────          ───────────────
工具操作                       概念定义（definition）            应届生版
数据分析                       流程步骤（steps）                 在职白领版
知识管理                       对比分析（contrast）              管理层版
编程辅助                       案例讲解（case_study）
效率工具                       工具演示（tool_demo）
项目实战                       实操考核（assessment）
```

三个维度正交交叉：同一个"工具操作"（如AI写作）可以呈现为概念定义、流程步骤、工具演示等不同形式；同一个"概念定义"可以为应届生、在职白领、管理层编译不同版本。

### 1.2 阶段A选定的3种Content Type

从AI_video_edu现有的6种graphic_type和8种layout/scene_type中，为阶段A选定3种高价值、高频使用的呈现形式：

| content_type | 对应原始ku_type | 培训场景占比 | 适用课程类型 |
|-------------|---------------|------------|------------|
| `concept` | definition + term_card | ~25% | 工具概念、核心术语、原理说明 |
| `steps` | flow + box_diagram | ~35% | 操作流程、步骤教学、使用方法 |
| `contrast` | contrast + comparison_table | ~15% | 工具对比、方案选择、优劣分析 |

**三种类型的总覆盖率**：约占培训内容的75%——满足阶段A的"覆盖80%常用类型"里程碑。

## 二、Content Type 详细定义（含审计条件）

### 2.1 `concept` — 概念/工具定义

**内容特征**：解释一个工具/术语/概念是什么、有什么用、核心特性。

**最佳呈现形式**：术语卡片（term_card）+ 框图（box_diagram）——标题+关键词+一句话定义+核心特性列表。

**严禁使用的形式**：长篇大论、纯文字段落、信息过载。

**原有graphic_type映射**：
- `term_card`：标题（≤10字）+ 定义（≤30字）+ 标签项（≤3个，每项≤8字）
- `box_diagram`：核心概念节点（≤5个）+ 关系边（≤6条）

**审计条件（7条）**：

| # | 审计条件 | 验证方式 | 级别 |
|---|---------|---------|------|
| C1 | 核心概念名称准确，与权威来源一致 | LLM自动校验 vs 知识库 | BLOCK |
| C2 | 定义包含"是什么+核心用途"两个要素 | 结构化检查（contains pattern） | BLOCK |
| C3 | 标签/特性数量≤3，每项≤8字 | Schema校验（maxItems/maxLength） | BLOCK |
| C4 | 无歧义表述——一个概念只用一个名称，全文一致 | 术语一致性检查 | WARN |
| C5 | 受众适配——应届生版用通俗语言，无未经解释的专业术语 | L2 LLM自检 | WARN |
| C6 | 图形不超认知负荷——节点≤5，边≤6 | 复杂度检测（现有style_guide） | BLOCK |
| C7 | narration与statement互补——statement给关键词，narration给完整解释 | 语义冗余度检查 | WARN |

### 2.2 `steps` — 流程/步骤教学

**内容特征**：按顺序展示操作步骤、使用方法、工作流程。

**最佳呈现形式**：步骤列表（steps layout）+ 流程图（box_diagram with arrows）。

**严禁使用的形式**：无序列表（无先后关系时可用）、文字墙。

**原有graphic_type映射**：
- `box_diagram`：步骤节点（≤8个）+ 顺序箭头（≤10条）
- `causal_chain`：因果或顺序链（≤6节点）

**审计条件（8条）**：

| # | 审计条件 | 验证方式 | 级别 |
|---|---------|---------|------|
| S1 | 步骤可执行——每步描述了一个学习者可以独立完成的操作 | LLM自检："如果我按这个步骤做，能完成吗？" | BLOCK |
| S2 | 前置条件明确——如果某步需要前置操作/软件/权限，已标注 | 关键词检查（"需要先""前提""确保"） | WARN |
| S3 | 步骤数量≤8（超过需拆分或降级为总览图） | Schema校验（maxItems=8） | BLOCK |
| S4 | 每步标签≤8字，完整描述在narration中 | Schema校验（maxLength） | BLOCK |
| S5 | 步骤间关系明确——顺序/并行/条件分支已标注 | 边类型检查（sequential/parallel/conditional） | WARN |
| S6 | 异常情况有处理——"如果这一步出错了怎么办"至少有提示 | 异常提示存在性检查 | WARN |
| S7 | 预期结果可验证——最后一步有"你应该看到/得到"的验证点 | 验证点存在性检查 | WARN |
| S8 | 工具操作类步骤有界面截图/示意图匹配（可选，阶段B） | — | INFO |

### 2.3 `contrast` — 对比/选择分析

**内容特征**：两个或多个工具/方案/方法的横向对比，帮助学习者做选择。

**最佳呈现形式**：对照表（comparison_table）+ 矩阵（matrix_2x2）。

**严禁使用的形式**：纯文字描述（看不出对比关系）、单一维度对比。

**原有graphic_type映射**：
- `comparison_table`：≤6行×≤3列——对比对象×对比维度
- `matrix_2x2`：固定4格——两个维度的四象限定位

**审计条件（7条）**：

| # | 审计条件 | 验证方式 | 级别 |
|---|---------|---------|------|
| R1 | 对比维度≥2——至少从两个角度对比 | Schema校验（cols≥3，含对象名列） | BLOCK |
| R2 | 对比对象≥2——至少有两个工具/方案 | Schema校验（rows≥2） | BLOCK |
| R3 | 每格单元格内容≤15字 | Schema校验（maxLength） | BLOCK |
| R4 | 对比结论明确——"什么场景选哪个"有结论 | 结论存在性检查 | WARN |
| R5 | 无偏见表述——避免"最好""完美"等绝对化用语 | 违禁词扫描 | BLOCK |
| R6 | 对比依据有来源——引用评测数据/官方文档/社区共识 | 引用存在性检查 | WARN |
| R7 | 选择建议有边界——"如果你X，选A；如果你Y，选B"而非"选A就对了" | 条件句式检查 | WARN |
