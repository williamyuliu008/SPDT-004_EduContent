## 一、项目定义

### 1.1 一句话定位

基于CGM构造管线+审计进化引擎，构建企业培训内容的自动化生产与持续优化系统。

### 1.2 要解决的问题

企业培训内容生产面临三重矛盾：
- **量**：新员工入职、合规更新、产品迭代、技能升级——培训内容需要持续高频产出
- **质**：培训内容错误（政策过时、流程不匹配、合规缺失）的后果从"浪费时间"到"法律风险"
- **人**：HR/L&D团队通常不是内容创作专家，却需要产出专业级培训材料

### 1.3 目标产出

```
输入: 培训需求一句话（"新员工入职培训，涵盖公司介绍/福利政策/IT安全/合规要求"）
  → CGM构造管线 → 
输出: 一套可直接使用的培训包
  ├─ 培训大纲（结构化的学习路径）
  ├─ 培训视频/课件（5-8个知识模块，Manim动画+TTS语音）
  ├─ 配套测试题（自动生成+自动评分）
  └─ 审计报告（L1-L3质量评分，需人工确认项清单）
```

### 1.4 成功标准

| 指标 | 阶段A目标 | 阶段B目标 |
|------|----------|----------|
| content_type覆盖 | 3种（入职须知/合规培训/技能培训）| 7±2种全覆盖 |
| 单模块生成时间 | <5分钟（含渲染） | <2分钟 |
| L2审计通过率 | >85% | >95% |
| 人工修改率 | <20%（每人天修改占比） | <5% |
| 学员理解度测试 | >70% | >85% |

## 二、技术架构（CGM+审计双层）

```
                         ┌──────────────────────┐
                         │   审计引擎（进化层）    │
                         │  L1: Schema校验       │
                         │  L2: 审计条件逐条验证  │
                         │  L3: 学员理解度测试    │
                         │  f(适应度) = rank选择  │
                         └──────────┬───────────┘
                                    │ 适应度反馈
┌───────────────────────────────────┼───────────────────────┐
│                      CGM 构造管线                          │
│  培训需求 → ADC(分类) → 参数生成 → 渲染 → Gate → 培训包    │
│            ku_type     Schema    Manim+   L1-L3  ┌─大纲    │
│            7±2种       填参      TTS+     ───→  ├─视频    │
│                                  字幕            ├─测试题  │
│                                                  └─审计报告│
└──────────────────────────────────────────────────────────┘
```

**关键设计决策**：
1. CGM负责"怎么做"——从需求到培训包的编译管线
2. 审计负责"怎么判断对、怎么变好"——L1-L3分层验证+进化选择
3. Spec-Audit同步定义——每种content_type在设计Schema的同时定义7±2条审计条件

## 五、关键风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 教学CGM的Manim渲染器对培训场景不够用 | 中 | 中 | Day 1先做适配性评估；若不适用则降级为PPT/HTML模板渲染 |
| LLM填参质量不达预期（<70%通过率） | 中 | 高 | 阶段A以人工填参为主，LLM填参仅做对比实验；积累few-shot示例库 |
| 审计条件定义不充分（漏掉关键失败模式） | 低 | 高 | Spec-Audit同步定义+Day 8审计结果驱动补充审计条件 |
| 学员测试资源不可用 | 高 | 低 | L3审计可选——阶段A的核心验证在L1-L2；L3留到阶段B |
