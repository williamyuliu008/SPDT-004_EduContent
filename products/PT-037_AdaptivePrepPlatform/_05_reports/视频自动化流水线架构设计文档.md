> 本文档回答：从「知识库中的知识」到「成品视频（MP4）」的完整链路如何设计。
> 目标：人在环路之外，系统全自动化闭环。
> 参考项目：PT-037 自适应备考平台（国美书法校考版）视频工厂

*文档版本：v1.0 | 日期：2026-07-15 | 状态：初稿，待讨论*

## 一、设计前提：两个约束

本架构在两个强约束下工作：

### 约束 A：AI 视觉能力远低于人类生物视觉

- 人类视觉：1 帧跳变可察觉；亿年生物进化优化
- AI 布局设计：规则积累极其有限；超出约束的创意几乎必然产生违规
- **结论**：不试图让 AI 设计画面，而是**让 AI 填模板**，模板由人类提前设计并像素验证

### 约束 B：音频是主通道，视频是锚点

- 音频在单位时间内传递更多信息（~150字/分钟）
- 视频画面承担：注意力锚定、重点强调、视觉结构化呈现
- **结论**：视频不是音频的「可视化翻译」，而是**知识结构的视觉投影**

```
│
└── 能力清单（Ability）

    ├ name: "句读捕捉力"

```

```
    ├→ 音频通道（知识传递主体）
    │   └→ TTS 旁白 → MP3
    └→ 视频通道（强调重点视觉）

    ↓ [动态时长合成]
最终 MP4（含 Overlay）
```

## 三、知识如何分流（音频 vs 视频）

### 3.1 分流原则

**不是「把同样的内容分别用音频和视频说一遍」，而是「把知识的不同维度分配给最合适的通道」。**

| 维度 | 分配给音频 | 分配给视频 |
|------|------|------|
| **知识传递** | ✅ 完整定义、历史背景、解释说明 | ❌ |
| **结构化呈现** | ❌ | ✅ 列表、对比、时间线、因果关系 |
| **视觉冲击力** | ❌ | ✅ 书体字形、名家真迹、碑帖图片 |
| **采分关键词** | ✅ 精确术语的读音 | ✅ 精确术语的文字呈现 |
| **流程步骤** | ✅ 心法口诀 | ✅ 操作步骤分解 |
| **易错警示** | ✅ 陷阱描述 | ✅ 对比示范（错误 vs 正确） |

### 3.2 知识类型 → 通道分配规则

```python
def route_knowledge(entry: KnowledgeEntry) -> RouteDecision:
    """
    基于知识类型和标签，决定音频/视频分配方案。
    """
    tags = set(entry.tags)
    question_types = entry.exam_tips.get("question_types", [])
    content = entry.structured_content

    # ── 规则 1：强视觉型知识 → 视频为主 ─────────────
    if any(t.startswith("#考点类型/译篆") for t in tags):
        # 译篆：重点展示篆形演变和对比
        return RouteDecision(
            audio_ratio=0.3,   # 旁白解释规则和陷阱
            video_ratio=0.7,   # 字形对比、演变过程
            primary_template="word_evolution",  # 展示篆→隶→楷演变
            secondary_template="contrast",       # 正误对比
            narration_focus="规则和陷阱说明"
        )

    # ── 规则 2：结构对比型 → 视频为主 ──────────────
    if any(t.startswith("#考点类型/名词解释") for t in tags):
        # 名词解释：四要素结构 → 视频分栏对比
        return RouteDecision(
            audio_ratio=0.6,   # 展开历史背景和评价
            video_ratio=0.4,   # 核心定义+代表作品
            primary_template="concept",    # 核心定义大字呈现
            secondary_template="timeline" # 历史脉络时间线
        )

    # ── 规则 3：流程步骤型 → 音频为主 ───────────────
    if any(t.startswith("#考点类型/句读") for t in tags):
        # 句读：先音频讲解断句逻辑，再视频展示标志词
        return RouteDecision(
            audio_ratio=0.7,   # 标志词讲解、语法结构
            video_ratio=0.3,   # 标志词标注
            primary_template="steps",  # 断句步骤
            secondary_template="concept"
        )

    # ── 规则 4：引言/书论型 → 音频为主，视频高亮 ───
    if entry.structured_content.get("is_quote"):
        return RouteDecision(
            audio_ratio=0.8,   # 完整引言朗读+解读
            video_ratio=0.2,   # 引言卡片高亮
            primary_template="quote_highlight",
            secondary_template="causal_chain"
        )

    # ── 默认：音频为主 ─────────────────────────────
    return RouteDecision(
        audio_ratio=0.6,
        video_ratio=0.4,
        primary_template="concept",
        secondary_template=None
    )
```

## 四、知识如何路由到模板

### 4.1 视觉模板库（当前已验证 10 种）

```
scene_type → 布局特征 → 适用知识类型
─────────────────────────────────────────────────────
title          中央主标题 → 章节封面
concept        核心概念 → 名词解释定义
steps          有序步骤列表 → 流程/断句/答题步骤
summary        要点列表 → 总结/采分要点
contrast       左右对比 → 正误对比/两种风格对比
dual_track    双轨并行 → 两个维度的并列对比
causal_chain  因果链 → 原因→结果逻辑
word_evolution 字形演变 → 书体演变/文化演进
timeline       垂直时间线 → 历史脉络/书家年表
quote_highlight 引言高亮 → 书论引言/名言警句
```

### 4.2 路由决策树

```python
def route_to_template(entry: KnowledgeEntry,
                     punct_text: PunctuationText = None,
                     ability: Ability = None,
                     difficulty: str = "Lv2") -> str:
    """
    给定知识条目，返回最优 scene_type。

    决策顺序：
      1. 是否有字形演变结构 → word_evolution
      2. 是否有时间线结构 → timeline
      3. 是否有因果关系 → causal_chain
      4. 是否为对比型 → dual_track / contrast
      5. 是否有引言 → quote_highlight
      6. 是否为流程步骤 → steps
      7. 是否为总结 → summary
      8. 默认 → concept
    """
    content = entry.structured_content if entry else {}
    tags = set(entry.tags) if entry else set()

    # ── 规则 1：书体/字形演变 ────────────────────
    if content.get("has_script_evolution"):
        return "word_evolution"

    # ── 规则 2：历史时间线 ────────────────────────
    if content.get("has_timeline") or "时间线" in entry.concept:
        return "timeline"

    # ── 规则 3：因果链 ────────────────────────────
    if content.get("cause_effect_pairs"):
        return "causal_chain"

    # ── 规则 4：双维度对比 ────────────────────────
    if content.get("dual_aspects"):
        return "dual_track"

    # ── 规则 5：正误对比 ─────────────────────────
    if entry and entry.exam_tips.get("common_mistakes"):
        return "contrast"

    # ── 规则 6：书论引言 ──────────────────────────
    if content.get("is_quote") or "引言" in entry.concept:
        return "quote_highlight"

    # ── 规则 7：流程/步骤 ─────────────────────────
    if ability and "步骤" in ability.name:
        return "steps"

    # ── 规则 8：总结/采分 ─────────────────────────
    if entry and entry.exam_tips.get("scoring_points"):
        return "summary"

    # ── 默认 ───────────────────────────────────────
    return "concept"
```

## 五、知识如何转化为 scene JSON

### 5.1 核心原则

**scene JSON 是「知识结构」到「视觉模板」的翻译层**。AI 不设计画面，只填充模板参数。

```python
@dataclass
class SceneJSON:
    scene_id: str           # "scene_01"
    scene_type: str          # "dual_track" — 来自路由决策
    scene_info: dict         # { idx, total, name, dur }
    content: dict           # 模板参数（模板决定，不允许自由发挥）
    narration: str           # 音频旁白（知识传递主体）
```

### 5.2 知识 → JSON 填充规则（示例：dual_track）

**输入**：宋四家 KnowledgeEntry
**输出**：scene JSON

```json
{
  "scene_type": "dual_track",
  "scene_info": {
    "idx": 2,
    "total": 10,
    "name": "宋四家",
    "dur": 25.0
  },
  "content": {
    "track_a": {
      "label": "书法家",
      "items": [
        "苏轼 — 丰腴跌宕",
        "黄庭坚 — 奇崛开张",
        "米芾 — 八面出锋",
        "蔡襄 — 淳淡婉美"
      ]
    },
    "track_b": {
      "label": "代表作",
      "items": [
        "《黄州寒食诗帖》",
        "《松风阁诗帖》",
        "《蜀素帖》",
        "《扈从帖》"
      ]
    }
  },
  "narration": "北宋时期，苏轼、黄庭坚、米芾、蔡襄并称宋四家。苏轼书法丰腴跌宕…"
}
```

**约束规则**：
- `items` 最多 4 条（模板固定）
- `label` 最多 8 字符（模板字号固定）
- `narration` 长度决定 `scene_info.dur`（`dur = 旁白时长 + 2s缓冲`）

### 5.3 各模板的内容字段规范

| 模板 | 必填字段 | 可选字段 | 字数限制 |
|------|---------|---------|---------|
| `title` | title, episode_label | — | title≤12字 |
| `concept` | keyword | description, highlights | keyword≤8字 |
| `steps` | steps[] | — | label≤12字 |
| `summary` | points[] | — | point≤30字 |
| `contrast` | wrong, right | — | 各≤20字 |
| `dual_track` | track_a, track_b | — | label≤8字，item≤20字 |
| `causal_chain` | header, chains[] | — | cause/effect各≤12字 |
| `word_evolution` | character, stages[] | subtitle | form≤4字，script≤6字 |
| `timeline` | header, events[] | — | year≤10字，event≤18字 |
| `quote_highlight` | quote, author | era, tag | **quote≤15字**（模板验证） |

## 六、旁白文案生成规则

### 6.1 旁白的职责

旁白是**知识传递的唯一主通道**，视频画面是注意力锚点。旁白决定场景时长。

### 6.2 旁白文案约束

```python
NARRATION_RULES = {
    # 语速：约 150 字/分钟（TTS 精英青年音色 0.9×）
    "max_chars_per_minute": 150,

    # 单场景旁白长度 → 场景时长
    # 规则：scene_dur = min(旁白字数/150*60 + 缓冲2s, 30s上限)

    # 内容结构：必须包含采分关键词
    "must_include": "exam_tips.scoring_points 至少出现 1 个",

    # 禁忌：不在旁白中描述画面（AI 无法验证视觉内容）
    "forbidden": [
        "注意看左边的...",
        "屏幕上显示的是...",
        "这幅图展示了..."
    ],

    # 音频格式：MP3 → 统一转 WAV 44100Hz stereo s16le
}
```

### 6.3 旁白文案生成 Prompt（知识 → 音频文本）

```markdown
你是一名国美书法校考辅导教师。请为以下知识条目生成一段旁白音频文本。

知识条目：
  concept: {concept}
  definition: {definition}
  考频: {考频星级}
  采分关键词: {scoring_points}
  易错点: {common_mistakes}

要求：
1. 字数：{target_chars} 字（目标时长 {target_dur}s）
2. 必须包含至少 1 个采分关键词
3. 不描述画面，只讲知识
4. 语言风格：简洁、专业、适合 TTS 朗读
5. 禁止出现「请看」「屏幕上」「图中」等视觉描述词
6. 输出：纯文本，不带任何格式标记
```

## 七、质量保障闭环

### 7.1 三层门禁

```
Layer 1: 内容门禁（生成时）
  └ AI 生成 scene JSON → schema 验证
    └ 必填字段检查 / 字数限制检查 / scene_type 存在检查

Layer 2: 渲染门禁（渲染时）
  └ Pillow 帧渲染 → 像素诊断
    └ 每场景随机抽 1 帧 → opaque px / 文字颜色 / 布局位置

Layer 3: 合成门禁（合成时）
  └ FFmpeg 音频视频合并 → 时长验证
    └ 视频时长 = 音频时长 ±0.5s / 无静默截断 / 无音视频错位
```

### 7.2 内容门禁（Layer 1）

```python
def validate_scene_json(scene_json: dict) -> ValidationResult:
    errors = []
    warnings = []

    st = scene_json.get("scene_type")
    if st not in VALID_SCENE_TYPES:
        errors.append(f"未知 scene_type: {st}")

    content = scene_json.get("content", {})

    # 字数门禁
    if st == "quote_highlight":
        quote = content.get("quote", "")
        if len(quote) > 15:
            errors.append(f"quote_highlight 引言超过15字：{len(quote)}字")
        if len(quote) < 5:
            warnings.append(f"quote_highlight 引言过短，可能视觉空旷")

    if st == "dual_track":
        for track_name in ["track_a", "track_b"]:
            track = content.get(track_name, {})
            items = track.get("items", [])
            if len(items) > 4:
                errors.append(f"{track_name} items 超过4条")
            for item in items:
                if len(item) > 20:
                    warnings.append(f"{track_name} item 过长：{item}")

    # 必填字段门禁
    required = REQUIRED_FIELDS.get(st, [])
    for field in required:
        if field not in content:
            errors.append(f"缺少必填字段: {field}")

    return ValidationResult(errors=errors, warnings=warnings)
```

### 7.3 像素门禁（Layer 2）

每个新模板首次使用前必须通过像素验证（参考 MODEL_PROMPT v1.3）。

```python
PIXEL_GUARD_RULES = {
    # 通用规则（所有模板）
    "total_opaque_min": 100_000,    # 整帧 opaque px 下限
    "no_full_transparent": True,     # t=0 时不能全透明
    "overlay_present": True,         # Overlay 进度条存在

    # 模板特定规则
    "contrast": {
        "wrong_card_opaque_min": 10_000,
        "right_card_opaque_min": 10_000,
    },
    "dual_track": {
        "label_bg_opaque_min": 5_000,  # label 背景 opaque（不透明色块）
        "column_border_opaque_min": 1_000,
    },
    "quote_highlight": {
        "accent_text_opaque_min": 500,   # ACCENT 引言文字
        "gold_tag_opaque_min": 100,      # GOLD 标签
        "white_attr_opaque_min": 200,    # WHITE 署名
        "border_opaque_min": 500,        # 边框
    },
}
```

### 7.4 合成门禁（Layer 3）

```python
COMPOSE_GUARD_RULES = {
    # 时长验证
    "duration_tolerance_s": 0.5,  # 视频 = 音频 ±0.5s

    # 音频验证
    "no_complete_silence": True,  # 全程无 -inf dB RMS
    "min_rms_db": -60,           # 最低 RMS ≥ -60 dB

    # PCM 数据量（排除 apad bug）
    "pcm_bytes_tolerance": 1000,   # expected_bytes - 44 ≈ actual_bytes ±1000
}
```

## 九、开放设计问题

### 问题 1：知识条目 → scene JSON 的自动化程度

当前：AI 根据模板规范手动填充 JSON
理想：给定知识条目，系统自动生成完整 scene JSON
**需要**：为每个模板设计「知识结构 → JSON 字段」的映射 Prompt

### 问题 2：多场景叙事连贯性

当前：每个场景独立渲染，无叙事连贯性
理想：相邻场景之间有视觉语言连贯性（色调/字体/动画节奏一致）
**需要**：定义全局视觉主题（theme），各模板共享主题参数

### 问题 3：知识库的「视频友好」标注

当前：`structured_content` 结构是为问答系统设计的
理想：知识条目包含 `video_template_hint` 字段，直接建议路由模板
**需要**：在 PT-037 知识条目中添加 `video_routing` 扩展字段

### 问题 4：互动层缺失

当前：视频是单向输出
理想：关键问题节点嵌入互动测试（答题 → 即时反馈）
**需要**：Agent4 出题 → 嵌入 scene JSON → 视频结尾展示问题
