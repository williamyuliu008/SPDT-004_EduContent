# BUILD-R × CGM 融合方法论

> 版本: v1.0 | 编制: 2026-07-13 | 适用: PT-037 AdaptivePrepPlatform

---

## 一、方法论融合背景

PT-037 平台同时继承了**两个工程方法论**：

- **BUILD-R**：本平台原创的通用自适应学习模型
- **CGM（约束型生成方法论）**：从 SPDT-004 传承，驱动知识→内容转化

两者在 PT-037 中形成**分工明确的协作关系**：
- BUILD-R 负责**学习体验层**（诊断→训练→反馈→进化）
- CGM 负责**内容生产层**（知识→题目→审计→入库）

---

## 二、BUILD-R 模型详解

| 字母 | 全称 | 职责 | 在 PT-037 的落地 |
|------|------|------|-----------------|
| **B** | Blueprint（蓝图） | 知识图谱构建 | Agent1 考纲解析 → Agent2 骨架搭建 |
| **U** | Utility（效用） | 能力转化 | Agent4 能力训练 + 心法手法体系 |
| **I** | Integration（整合） | 跨包联动 | Agent5 跨配置包缝合调度 |
| **L** | Library（剧本库） | 错题管理 | 错题剧本化 + 微剧本推送 |
| **D** | Drama（戏剧化） | 学习动机 | 微剧本 + 艾宾浩斯曲线驱动 |
| **R** | Revision（进化） | 持续优化 | 对抗式审计 + 效果评估反馈 |

## 三、CGM 方法论在 PT-037 的落地

```
知识条目输入
    │
    ▼
约束层（配置包专属模板 + 标签体系）
    │
    ▼
生成层（Agent4 出题 / Agent2 知识条目撰写）
    │
    ▼
审计层（Agent2 对抗式 Critic 审查）
    │
    ├── PASS → 入库（Neo4j / PostgreSQL）
    ├── NEED_REVISION → 打回生成层
    └── REJECT → 废弃
```

**约束维度**：
- 标签合规（考频/认知层级/考点类型）
- 边界约束（一简对多篆、外推范围）
- 采分点对齐（与 Agent1 考纲映射一致）
- 文风约束（配置包专属 Prompt 补丁）

## 四、双方法论协作流程

```
用户开始学习
    │
    ▼
Agent5（S/C/F/I状态感知）→ 决策：该练什么
    │
    ├── 优先级1：熔断保护（C≥8 或 F≥3）→ 微剧本
    ├── 优先级2：核心优先 → Agent4 Lv2/Lv3训练
    ├── 优先级3：跨包联动 → Agent5 多包缝合
    └── 优先级4：节奏控制 → 学-练-测-玩循环

训练结束后
    │
    ▼
Agent2 对抗式审计（新生成的知识条目 / 错题剧本）
    │
    ▼
CGM审计通过 → 入库 + 更新用户画像（S值变化）
    │
    ▼
Agent3 可视化更新（知识星系图 + 掌握热力图）
    │
    ▼
下一轮 Agent5 调度决策
```

## 五、与 SPDT-004 CGM 审计的差异

| 维度 | SPDT-004 内容 PDT | PT-037 平台 |
|------|-------------------|-------------|
| 审计对象 | 视频/课件/试题 | 知识条目 + 错题剧本 |
| 审计重点 | 教学效果 + 视频质量 | 事实准确性 + 应试有效性 |
| 审计频率 | 每日抽检 | 实时（每条入库前） |
| 审计模型 | Gen+Critic | Gen+Critic（书法专业Critic） |

---

## 六、关键设计原则

1. **平台中立**：平台层不包含任何具体学科内容
2. **配置包自治**：每个配置包独立维护自己的知识库和模板
3. **审计前置**：所有内容入库前必须通过 CGM 审计
4. **跨包透明**：Agent5 调度时对用户屏蔽跨包边界
5. **记忆共享**：全局记忆体对所有 Agent 可见，但各 Agent 有读写权限分级
