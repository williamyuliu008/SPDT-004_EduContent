各阶段检查项

阶段核心检查失败对策
PREFLIGHT 8 项检查: build-profile API24、oh-package modelVersion、hvigor-config、app.json5 bundleName、module.json5、pages/*.ets 非空、品牌色一致性、跨品牌代码污染 阻塞后续，修复后重跑
BUILD hvigorw assembleHap 并行编译，每 APP 独立进程，提取 ERROR/WARN 计数 人工介入修复 → 重跑
SIGN hap-sign-tool.jar 自动签名，复用已有 debug profile 人工介入修复 → 重跑
DEPLOY hdc install + hdc shell aa start 冷启动验证（仅当设备连接时） 可选阶段，无设备不阻塞
REPORT 通过/失败/跳过统计，HAP 大小对比，警告趋势，品牌 JSON + MD 报告 始终生成，不阻塞

5. 新增品牌操作清单

Step 1 · 复制模板
复制 pdt_registry/_template_harmony/ → pdt_registry/HDT-001-XX/，修改品牌名/色/赛道
Step 2 · 品牌声明
在 SPDT-001 spdt.yaml 的 sub_pdts 中注册新品牌
Step 3 · CI 品牌配置
在 ci/pipeline.yaml 的 brands 下添加新品牌（prefix + 质量策略）
Step 4 · 首个 APP 生成
从 templates/base fork → SDC 批量生成品牌 APP 骨架 → PREFLIGHT 校验
Step 5 · CI 自动接管
子PDT激活 → CI 自动触发 PREFLIGHT → BUILD → SIGN → REPORT

新增一个品牌，从模板到首个 APP 编译通过 ≤ 30 分钟，其中 CI 自动化部分 ≤ 5 分钟。

8. 风险与对策

风险对策
品牌间代码污染（已验证发生: craftsman-arkui 含 ThinkKit mock）PREFLIGHT 阶段自动检测跨品牌 import；Craftsman 品牌 CI 强制 extra check
SDK 版本漂移（真机 API 24 vs DevEco API 26）PREFLIGHT 校验 compatibleSdkVersion 必须包含 24；SDK 版本变更需 SPDT 级审批
多品牌并行编译争抢 hvigor daemonCI 品牌级排队（max_parallel_brands=1，串行不同品牌）；同品牌 APP 并行编译
签名证书过期sign-all.ps1 中的自建 CA 有效期 3650 天；每年更新一次
品牌数量增长后资源碎片化SPDT 统一资源池 + 品牌按里程碑申请额度 + OGC 审计使用效率
