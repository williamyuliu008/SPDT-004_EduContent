## 一、产品定位

**一句话：** 鸿蒙生态的 AI 编程入口——"说需求，出代码，审质量，建项目"。

HarmonyCoder 不是代码补全工具，而是**全链路 AI 编程伙伴**。开发者从"想做什么"到"跑起来看"，全程在 APP 内完成。

**与竞品差异：**

| | ChatGPT/Claude | GitHub Copilot | HarmonyCoder |
|:---|:---|:---|:---|
| 专注领域 | 通用 | 通用编码 | **ArkTS/HarmonyOS 专精** |
| 代码审查 | 无 | 建议级 | **自动审查+修改+验证** |
| 项目脚手架 | 无 | 无 | **一键生成完整项目** |
| OHPM 感知 | 无 | 无 | **10 个官方库深度集成** |
| 离线可用 | 否 | 否 | **基础功能离线** |
| 鸿蒙设备原生 | 否 | 否 | **是** |

## 二、功能全景（智能体增强后）

### 四大模块

```
HarmonyCoder
├── 1. AI 代码问答 — 自然语言交互式编程
├── 2. 代码审查引擎 — 自动 Review + Fix
├── 3. 项目脚手架生成器 — 从需求描述到完整项目
└── 4. OHPM 智能推荐 — 10 个官方库深度集成
```

## 三、模块详解

### 模块 1：AI 代码问答

**入口：** APP 首页底部的对话输入框，或任意代码/场景页面的右下角浮动按钮。

**工作流程：**

```
用户输入 "如何用 ArkTS 实现一个下拉刷新列表？"
    │
    ▼
[数据捕获模块] 自动获取当前位置上下文
    │  (如果在代码页 → 附上当前代码片段)
    │  (如果在场景页 → 附上场景描述)
    ▼
[问答助手智能体] 检索 ArkTS 知识库 + OHPM 库文档
    │
    ▼
返回三段式回复:
  ┌─────────────────────────────────┐
  │ 📋 代码示例                        │
  │ @Entry @Component struct Demo {   │
  │   ...完整可运行代码...              │
  │ }                                 │
  ├─────────────────────────────────┤
  │ 💡 关键说明                        │
  │ · pulltorefresh 组件用法          │
  │ · 需要配置 module.json5           │
  ├─────────────────────────────────┤
  │ 🔧 操作                            │
  │ [复制代码] [新建文件] [添加到项目]    │
  └─────────────────────────────────┘
```

**智能体增强：**
- 跨页上下文：用户在列表页问"这个列表能加刷新吗？"，Agent 自动识别当前页面数据并给出针对性代码
- 追问记忆：用户连续问 3 个问题，Agent 保持上下文，"刚才那个例子换成上拉加载怎么改？"
- 代码操作：回答中的"添加到项目"按钮→Agent 自动在当前项目中创建文件并写入代码

### 模块 2：代码审查引擎

**入口：** 项目详情页 → "审查"标签 → 选择文件或全项目审查。

**工作流程：**

```
选中 3 个 .ets 文件 → 点击 "AI 审查"
    │
    ▼
[流程自动化智能体] 分三步:
  Step 1 — Generator: 逐行分析代码
  Step 2 — Critic:   对照 ArkTS 规范检查 5 个维度
  Step 3 — Fixer:     生成修改建议
    │
    ▼
审查报告:
  ┌──────────────────────────────────────┐
  │ 📊 审查概览                            │
  │ 文件: 3 | 总行数: 247 | 问题: 4 处      │
  ├──────────────────────────────────────┤
  │ 🔴 必须修复 (2)                        │
  │ · Index.ets:22 — router.forEach 已废弃 │
  │ · Page2.ets:8 — 未做空值检查            │
  ├──────────────────────────────────────┤
  │ 🟡 建议优化 (2)                        │
  │ · Page2.ets:156 — 可提取为公共组件      │
  │ · Index.ets:89 — 建议用 LazyForEach    │
  └──────────────────────────────────────┘
  操作: [一键修复必须项] [逐项确认] [生成报告文档]
```

**智能体增强：**
- **自动修复闭环：** 点击"一键修复" → Agent 修改代码 → 自动 `devecocli lint` 验证 → 无新错误则提交
- **品牌色检查：** 自动检测是否使用了品牌色 #7B2D8E，如果不是则建议替换
- **污染检测：** 检查是否不小心 import 了其他品牌的组件
- **历史追踪：** 每次审查结果存档，可对比上次审查后的改进情况

### 模块 3：项目脚手架生成器

**入口：** 首页 "新建项目" 卡片。

**工作流程：**

```
用户输入:
"创建一个习惯打卡APP，有首页(显示今日习惯)、添加页(设置习惯名称/频率)、统计页(折线图)"
    │
    ▼
[流程自动化智能体] 三步走:
  Step 1 — 需求解析: 识别出 3 个页面 + 1 个数据模型
  Step 2 — 架构建模: 生成 arkts-codegen-skeleton 完整项目结构
  Step 3 — 代码生成: 为每个页面生成 ArkTS 代码
    │
    ▼
生成摘要:
  ┌──────────────────────────────────┐
  │ 🏗️ 项目脚手架已生成                │
  │ 项目名: habit-tracker             │
  │ 页面: Index / AddHabit / Stats    │
  │ 数据模型: HabitItem (4个字段)      │
  │ 预估 HAP: ~32KB                   │
  ├──────────────────────────────────┤
  │ 预览:                             │
  │ ┌─────────┐ ┌─────────┐ ┌──────┐ │
  │ │ 今日习惯  │ │ 添加习惯  │ │ 统计  │ │
  │ └─────────┘ └─────────┘ └──────┘ │
  └──────────────────────────────────┘
  操作: [下载项目] [在 APP 中预览] [一键部署到设备]
```

**智能体增强：**
- 生成后自动调用 `devecocli run` 部署到连接的设备
- 支持"在这个基础上修改"的迭代对话
- 自动填充 `app.config.ts`、品牌色、bundleName
- 与 `init-app.ps1` 模板对接，生成的代码遵循 SPDT-001 规范

### 模块 4：OHPM 智能推荐

**入口：** 每个代码相关页面底部，或通过首页"三方库"标签。

**当前能力：** 10 个官方库的静态推荐列表。

**智能体增强后：**

```
用户在对话中说 "我需要网络请求"
    │
    ▼
Agent 检索 OHPM 知识库 → 推荐 @ohos/axios
    │
展示:
  ┌──────────────────────────────────┐
  │ @ohos/axios — HTTP 网络请求       │
  │ 标签: 网络 · API · 数据           │
  │ 安装: ohpm install @ohos/axios   │
  ├──────────────────────────────────┤
  │ 📄 在项目中使用:                   │
  │ import axios from '@ohos/axios'; │
  │ axios.get('https://api.xxx')     │
  │   .then(res => ...)              │
  ├──────────────────────────────────┤
  │ 操作: [一键安装] [查看完整文档]      │
  └──────────────────────────────────┘
```

## 四、用户使用场景

### 场景 A：新手开发者第一个 APP

1. 打开 HarmonyCoder → 首页
2. 在对话输入"我想做一个 Todo 清单 APP"
3. Agent 通过反问确认需求："需要哪些功能？简单的增删改查还是含分类/提醒？"
4. 用户回复后 → Agent 调用脚手架生成器 → 生成完整项目
5. 点击"部署到设备" → APP 出现在手机上
6. 用户打开 APP 发现首页太简陋 → 对话 "首页能不能加个空状态提示"
7. Agent 修改 Index.ets → 自动审查 → 重新部署

### 场景 B：经验开发者代码优化

1. 用户打开自己的项目 → 进入"审查"标签
2. 点击"全项目审查"
3. Agent 扫描 18 个文件 → 报告 7 个问题（3 个必须修复，4 个建议）
4. 点击"一键修复必须项" → Agent 自动修改 → 再次审查确认无新问题
5. 导出审查报告 PDF → 分享给团队

### 场景 C：学习 ArkTS

1. 用户在对话中问"@State 和 @Link 有什么区别？"
2. Agent 返回对比表格 + 代码示例
3. 用户追问"给我一个完整的父子组件通信例子"
4. Agent 生成完整代码 → 用户点"新建文件试一下"
5. 代码中出现语法错误 → Agent 自动捕获并建议修复

## 五、技术架构

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  ArkTS 前端   │  │  智能体中台   │  │  本地能力层   │
│  (对话界面)   │  │  (5大模块)   │  │  devecocli    │
│  (代码预览)   │◄─┤  -数据捕获   │◄─┤  hvigor       │
│  (审查报告)   │  │  -权限校验   │  │  ohpm         │
│  (脚手架预览)  │  │  -执行队列   │  │  hdc          │
└──────────────┘  │  -审计日志   │  └──────────────┘
                  │  -对话管理   │
                  └──────┬───────┘
                         │
                  ┌──────┴───────┐
                  │  OMAS 后端    │
                  │  SDC (代码生成) │
                  │  CMC (报告渲染) │
                  │  Design SOP    │
                  │  (Agent 集群)  │
                  └──────────────┘
```

**部署模式：** 所有核心功能本地运行。复杂代码生成可联动云端大模型，但基础审查/脚手架/OHPM 推荐全部离线可用。
