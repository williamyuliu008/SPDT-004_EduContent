# "小龙虾设计"文档 · 对鸿蒙APP的价值评估

> 来源: 0707-小龙虾设计 (23章对话) | 评估: 鸿蒙特使 | 2026-07-16

---

## 一、文档核心框架

"小龙虾"是 AI Agent 产品设计的完整方法论，覆盖 6 层：

```
产品定位（DRD） → 架构（ADS） → 协作（SHARED_CTX） → 学习演化 → UI/UX → 测试体系
```

**23 章对话提炼出 4 类 Agent 产品形态、3 层安全体系、3 面板 UI 架构、5 层测试框架。**

---

## 二、对鸿蒙 APP 的价值评估

### 高价值（直接可复用）

| 小龙虾概念 | 鸿蒙应用 | 效果 |
|:---|:---|:---|
| **三面板 UI 架构** | Agent 对话界面设计 | 左侧上下文+中间对话+右侧面板 → 直接用于 harmonycoder 的"代码审查"界面 |
| **Diff-First 审查模式** | Agent 修改确认 | 修改前/后对比 → thinkkit-* 所有 APP 的 Agent 确认弹窗 |
| **四色视觉系统** | 品牌 Agent 组件 | 蓝(思考)/黄(警告)/绿(成功)/红(危险) → 5 品牌的 Agent 浮标配色基础 |
| **Panic Button 机制** | Agent 紧急停止 | 所有 Agent 功能的"停止"按钮 → 用户安全感 |
| **DRD 模板** | 新 APP 立项 | 产品定位/功能需求/非功能需求/边界范围 → 可嵌入 init-app.ps1 |

### 中价值（需适配后复用）

| 小龙虾概念 | 鸿蒙应用 | 适配成本 |
|:---|:---|:---|
| **SHARED_CTX/ 协议** | 统一数据协议 | 接口定义/领域模型/架构决策 → 对应已有的"实体→值→权限"协议 |
| **四级测试体系 (L1-L4)** | Agent 质量保证 | 静态检查/安全测试/语义测试/技能测试 → 对应 PREFLIGHT + OGC |
| **Agent 人格设计 (SOUL.md)** | app.config.ts 扩展 | 不同 Agent 类型的"人格"差异 → 需新增 AgentProfile 字段 |
| **Docker 沙箱** | 不适用（鸿蒙是移动 OS） | 改用 ArkTS IPC 隔离 → 成本高 |
| **多 Agent 舰队模式** | harmonycoder 多角色 | Chief+Dev+Test+Docs → 需 Design SOP 生成 |

### 低价值（暂不适用）

| 小龙虾概念 | 原因 |
|:---|:---|
| Docker 容器部署 | 鸿蒙是真机部署，非容器化 |
| git commit 工作流 | 鸿蒙 APP 无需 Git 操作 |
| 命令行 Agent 交互 | 鸿蒙是触屏 APP，非 CLI |

## 三、立刻可引入的三个设计

### 3.1 Agent 对话界面三面板布局

```
┌─────────────────────────────────────┐
│ [harmonycoder]         [⚡停止] [⚙] │ ← Header
├────────┬────────────────┬───────────┤
│ 上下文  │     对话区       │  检查器   │
│        │                │           │
│ 当前文件 │ 你: 审查这段代码  │ 文件树     │
│ Index.ets│ AI: 发现2个问题  │ 历史记录   │
│        │ [diff 预览]     │ Token用量  │
│ 任务状态 │                │ 操作日志   │
│ 审查中.. │ [确认修复][忽略]  │           │
├────────┴────────────────┴───────────┤
│ [输入你想要的...              ][发送] │ ← Footer
└─────────────────────────────────────┘
```

**直接用 harmonycoder 实现：** 左侧=当前项目文件树，中间=对话+Diff，右侧=审查结果面板。

### 3.2 四色+一白的视觉标记体系

| 颜色 | 含义 | 鸿蒙 APP 使用场景 |
|:---|:---|:---|
| 🔵 蓝 | Agent 思考中 / 读取数据 | 所有 Agent 浮标"思考"状态 |
| 🟡 黄 | 警告 / 需要确认 | 修改前的 Diff 预览弹窗 |
| 🟢 绿 | 成功 / 安全 | 操作完成、审查通过 |
| 🔴 红 | 危险 / 失败 / 紧急停止 | 删除操作、代码审查失败 |
| ⚪ 灰白 | 中性 / 信息 | 普通对话消息 |

### 3.3 产品设计需求 (DRD) 模板

小龙虾提供了 6 维设计模板，直接适配到 HarmonyCoder 产品蓝图：

| DRD 维度 | HarmonyCoder 对应 |
|:---|:---|
| 产品定位 | "鸿蒙生态 AI 编程入口" |
| 功能需求 | 代码问答 / 审查 / 脚手架 / OHPM |
| 安全约束 | 只读项目文件 / 禁止网络请求 / 禁止执行系统命令 |
| 非功能需求 | 响应 <3s / 离线可用 / 暗色模式 |
| 边界范围 | 仅代码仓库 / 不涉及IM/协作/部署到非目标设备 |
| 演化路径 | L1(静态检查) → L2(安全约束) → L3(语义测试) → L4(技能测试) |
