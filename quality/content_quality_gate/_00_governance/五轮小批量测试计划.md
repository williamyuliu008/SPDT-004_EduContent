# 小批量测试五轮计划 — 编译器与现实校准

> 日期：2026-07-04 | 目的：通过结构化的小批量生产→人类审查→编译器升级循环，将编译器从v0.2提升至v0.5

---

## 一、校准策略

```
每轮流程：
  生产2-3个新视频 → 人类100%首审 → 发现bug(A) 
                                     → 编译器是否已检测到(A)?
                                        YES → 编译器正确，记录统计
                                        NO  → 编译器盲区！
                                              → 分析根因
                                              → 编译器升级（新Gate/增强现有Gate/新增金标样本）
                                              → 新增变异注入
                                              → 重新验证
```

**核心机**：人类的每次审查不是"消耗"——是给编译器注入新的失败模式。每个bug都是一次编译器升级。

## 二、五轮计划

| 轮次 | 生产内容 | 人类审查 | 累计金标 | 目标正确率 |
|------|---------|:---:|---------|:---:|
| R1 | T04+T05（6 Scene） | 100% | 24→30 | 85% | ✅ 0 bug |
| R2 | T06+T07+T08（9 Scene） | 100% | 30→39 | 88% | ⏳ |
| R3 | T09+T10+DRAM终版（10 Scene） | 80% | 39→49 | 92% | ⏳ |
| R4 | 全10课打包+DRAM（15 Scene） | 50% | 49→64 | 95% | ⏳ |
| R5 | 跨域验证（法律文书x5 Scene） | 20% | 64→69 | 98% | ⏳ |

**人类审查递减路径**：R1/R2=100%（编译器不成熟）→ R3=80%（编译器已校准主要模式）→ R4=50%→ R5=20%（编译器可信）。

## 三、每轮的输出规范

每轮生成一份标准化报告：

| 字段 | 说明 |
|------|------|
| 人类发现bug数 | N |
| 编译器检测到数 | M（M/N = 检出率） |
| 编译器漏检数 | N-M |
| 本轮升级 | 新Gate？增强Gate？新金标？新变异？ |
| 升级后重新验证 | 金标正确率 + 变异检出率 |
| 人类审查时长 | 分钟数 |

## 四、停止条件

并非无限循环。满足以下**全部三个条件**时，人类审查可以从20%继续降低至5%：

1. 连续2轮人类审查无新增编译器盲区（即所有人类发现的bug编译器都已检测）
2. 金标正确率 > 98%且持续2轮
3. 变异检出率 > 95%且持续2轮

达到后→编译器v1.0正式发布→人类审查降至5%抽检→进入Stage C（LLM自动化代码生成+编译器全自动验证）。
