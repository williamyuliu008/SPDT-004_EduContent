## 五、金标测试集管理规范

### 样本格式

每个金标样本包含：
- `scene.json` — 场景数据（正确的或有缺陷的）
- `expected.json` — 预期各Gate结果 `{G01: PASS/FAIL, G03: PASS/FAIL, ...}`
- `meta.yaml` — 元信息（来源、缺陷类型、添加日期、scene_type）

### 版本发布流程

```
1. 编译器代码变更
2. 跑全量金标测试集 → 正确率统计
3. 若正确率下降 → 修复或回滚
4. 若正确率上升/持平 → 发布新版本
5. 每新增10个金标样本 → 打一个minor版本
6. 每次跨领域验证通过 → 打一个major版本
```

### 采样密度升级路径

```
v0.1: 每条需求1-2样本（覆盖性验证）
  → 采样密度 = "能不能检测到这个缺陷类型"
v0.3: 每条需求3-5样本（边界带验证）
  → 采样密度 = "能不能在边界值附近准确判定"
v1.0: 每条需求10+样本（统计验证）
  → 采样密度 = "检出率和误报率在统计意义上可信"
```
