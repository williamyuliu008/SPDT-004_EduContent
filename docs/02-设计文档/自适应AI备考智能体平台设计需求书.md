# 自适应AI备考智能体平台：设计需求书

**文档版本**：V1.0
**编制日期**：2026年7月13日
**编制依据**：基于 BUILD-R 模型与国美书法备考实践

---

## 一、整体架构：平台 + 配置包

本系统的核心设计理念是**"通用引擎 + 专用内容包"**的解耦架构。

```
┌─────────────────────────────────────────────────┐
│              用户交互层（Web / APP）               │
├─────────────────────────────────────────────────┤
│                 智能体调度层（Agent 5）             │
│         状态感知 | 路径规划 | 跨包联动 | 熔断保护    │
├─────────────────────────────────────────────────┤
│    Agent 2（审计） │ Agent 4（训练）│ Agent 3（可视化）│
├─────────────────────────────────────────────────┤
│               全局记忆体（Global Memory）           │
│  用户画像 │ 知识图谱（通用骨架）│ 错题剧本库 │ 学习轨迹  │
├─────────────────────────────────────────────────┤
│                   平台核心层                       │
│   考纲解析 │ 标签体系 │ 出题引擎 │ 对抗审计 │ 多端同步  │
├──────────────┬──────────────────┬────────────────┤
│   配置包A     │   配置包B         │   配置包C       │
│  （国美书法）  │   （高考历史）     │   （高考地理）   │
│              │                  │               │
│ 知识库       │ 知识库           │ 知识库         │
│ 能力清单     │ 能力清单         │ 能力清单       │
│ 专属Prompt   │ 专属Prompt       │ 专属Prompt     │
│ 训练剧本     │ 训练剧本         │ 训练剧本       │
│ 考纲映射     │ 考纲映射         │ 考纲映射       │
└──────────────┴──────────────────┴────────────────┘
```

**关键设计原则**：

- **平台层**只负责"怎么学"，不包含任何具体学科内容
- **配置包**只包含"学什么"，与平台通过标准化接口对接
- 新增一个学科 = 新增一个配置包，无需修改平台代码
- 跨学科综合训练由 Agent 5 调度多个配置包联动实现

## 二、平台核心层需求

### 2.1 系统愿景

打造一个由多个 AI Agent 协同工作的「自适应备考操作系统」：

> 不仅存储知识，更能模拟名师思维，进行个性化诊断与训练，让学习从「刷题」升级为「建城」。

**目标用户**：高中阶段参加高考/校考的学生及其教师/家长
**核心价值**：将"备考"从线性累加（刷题）升级为生态构建（挖地基、盖楼房、修路网）

### 2.2 智能体集群设计

#### Agent 1：考纲解析与标引（The Analyst）

**职责**：处理输入源，建立知识库的基础元数据

**输入源**：

- 教育部颁发的各学科考试大纲（PDF/网页）
- 近10年高考/校考真题（结构化录入）
- 权威教辅材料的知识点目录

**核心功能**：

| 功能 | 描述 | 技术要求 |
|------|------|----------|
| 结构化提取 | 将考纲文本转化为 JSON/知识图谱节点 | NLP + 规则引擎 |
| 考频分析 | 统计各知识点在历年真题中出现频次 | 文本挖掘 + 索引 |
| 难度标定 | 结合布鲁姆认知分类法（记忆/理解/应用/分析/评价/创造）标注 | 人工+AI混合 |
| 三级标注 | 标注知识点间的依赖关系（前置/后置/并列） | 图数据库（Neo4j） |

**输出**：`知识点节点`（含ID、名称、描述、考频星级、认知层级、依赖关系、考纲出处）

---

#### Agent 2：知识架构与审计（The Architect & Auditor）

**职责**：构建知识库并确保准确性（系统的「质量守门员」）

**核心功能**：

**① 骨架搭建**

- 根据学科逻辑建立主干树状图
  - 历史：时间轴（朝代→重大事件→人物→制度）
  - 地理：空间轴（区域→区位→人地关系）
  - 书法：书体轴（篆→隶→楷→行→草）× 朝代轴 × 流派轴
- 支持多维度视图切换

**② 多维标签体系**

| 标签维度 | 示例 | 说明 |
|----------|------|------|
| `#学科` | `#学科/书法史` `#学科/古代汉语` | 一级分类 |
| `#模块` | `#模块/隋唐书法` `#模块/说文解字` | 二级分类 |
| `#考点类型` | `#考点/名词解释` `#考点/译篆` | 考试形式 |
| `#认知层级` | `#认知/记忆` `#认知/分析` | 布鲁姆分类 |
| `#考频` | `#考频/⭐⭐⭐⭐⭐` | 优先级 |
| `#关联考点` | `#关联/安史之乱` `#关联/金石学` | 跨知识点连接 |
| `#外推范围` | `#外推/一级` `#外推/二级` | 知识边界管理 |

**③ 对抗式审计（核心创新）**

```
┌─────────────────┐
│  待入库知识点草稿  │
└────────┬────────┘
         ▼
┌─────────────────┐     ┌──────────────────┐
│  生成模型（Gen）  │────▶│  批判模型（Critic）│
│  撰写知识点解释   │     │  扮演「杠精教授」  │
└─────────────────┘     │  专门挑刺         │
                        └────────┬─────────┘
                                 ▼
                      ┌──────────────────┐
                      │ 审核结果          │
                      │ PASS / NEED_REVISION / REJECT │
                      └──────────────────┘
```

**Critic 审计维度**：

- 事实核查：时间、地点、人物、专有名词是否准确
- 逻辑诊断：因果关系是否成立，有无因果倒置或强加因果
- 概念界定：是否混淆"原因/背景"、"特点/影响"
- 应试有效性：该知识点是否有助于得分

**④ RAG 增强**

接入权威资料库（教辅、史籍、字典原文），Agent 2 在审核时携带上下文，规避幻觉错误。

#### Agent 3：可视化与交互（The UI/UX Agent）

**职责**：负责数据的多端呈现与交互体验

**Web 端功能**：

| 功能 | 描述 |
|------|------|
| 知识星系图 | 核心考点是高亮恒星，边缘知识是行星，连接线是关联度 |
| 掌握热力图 | 全局视图查看各知识点掌握情况 |
| 能力雷达图 | 展示各能力维度（译篆/句读/史论/创作）的当前水平 |
| 进度时间轴 | 显示学习轨迹与复习计划 |
| 实时状态面板 | 展示 S/C/F/I 四维状态 |

**移动端 APP 功能**：

| 功能 | 描述 | 使用场景 |
|------|------|----------|
| 闪卡复习 | 基于艾宾浩斯遗忘曲线推送 | 碎片时间 |
| 微剧本推送 | 每日一条历史角色独白或情境题 | 放松学习 |
| 扫码识题 | 拍照上传，调用 Agent 2/4 解析 | 纸质教辅 |
| 语音问答 | 语音输入问题，AI 语音回复 | 通勤场景 |
| 错题剧本回顾 | 推送当日错题的"错题剧本"提醒 | 睡前复习 |

---

#### Agent 4：能力训练与出题（The Coach）

**职责**：「练」的环节，实现生成式学习

**核心方法论**：

**① 心法-手法体系**（从国美书法备考实践中提炼）

| 能力点 | 破题心法 | 答题手法 |
|--------|----------|----------|
| 译篆 | 以义定形，以部推字 | 先拆分部首，再按《说文》标准组合 |
| 句读 | 先标人名/曰云/也矣，再切排比 | 找固定结构标志词，逐层切分 |
| 名词解释 | 定性→展开→采分→评价 | 四句公式，150–200字 |
| 简答论述 | 破题→背景→特征→总结 | 四段骨架，史论结合 |

**② 难度分级（Scaffolding）**

| 级别 | 描述 | 示例 |
|------|------|------|
| Lv1 | 单一知识点，直接考察记忆或简单理解 | 写出"斗争"的篆书 |
| Lv2 | 双知识点关联，考察理解与应用 | 结合安史之乱背景，分析颜体风格成因 |
| Lv3 | 跨学科综合，考察分析与评价 | 以书法为切入点，论述唐代文人精神 |

**③ 错题剧本化（Error Scripting）**

不记录"原因：粗心"，而是构建「微观剧本」：

> 例（书法）："公元2026年，你在考场上看到'繁复'两个字，毫不犹豫地写下了'復'。但正确答案是'複'。此刻，你作为一个书法考生，需要补上'衣部=重复/重叠'这条逻辑链。"

**④ 动态出题引擎**

- 根据用户画像（S/C/F/I）自动选择难度
- 检测到某能力薄弱时，自动生成 10–20 道同类变式题
- 支持"专项突破"模式：用户指定薄弱点，Agent 4 生成强化训练集

---

#### Agent 5：全局调度与推荐（The Conductor）

**职责**：系统的「大脑」，决定"现在该学什么、该练什么"

**用户状态模型**：

| 维度 | 全称 | 范围 | 说明 |
|------|------|------|------|
| **S** | Score（掌握度） | 0–100% | 来自答题正确率与 Agent 2 的标签 |
| **C** | Cognitive Load（认知负荷） | 1–10 | 实时监测 |
| **F** | Fatigue（疲劳值） | 0–∞ | 连续学习累积 |
| **I** | Interest（兴趣指数） | 1–10 | 停留时长、主动提问、创作得分 |

**决策优先级**：

```
优先级1：熔断保护
  if C >= 8 or F >= 3:
    → Agent 3（微剧本/低功耗模式）

优先级2：核心优先（80/20法则）
  if 五星考点 S < 80%:
    → C <= 5 ? Agent 4(Lv3) : Agent 4(Lv2)

优先级3：跨学科联动
  if 当前学习触发跨包关联:
    → Agent 4（缝合训练）

优先级4：节奏控制
  - Agent 2 连续调用 <= 20分钟
  - Agent 4 连续调用 <= 30分钟
  - 遵循"学-练-测-玩"循环
```

**跨包联动示例**：

```
用户正在学习「安史之乱」（历史配置包）
    ↓
Agent 5 发现关联：书法配置包中的「颜真卿在蒲州」
    ↓
Agent 5 发现关联：地理配置包中的「蒲州地形」
    ↓
调度 Agent 4 生成跨包缝合题：
  "分析蒲州地理位置对颜真卿平叛策略及书法风格的影响"
```

### 2.3 全局记忆体（Global Memory）

**设计要求**：所有 Agent 共享读写，数据持久化存储

| 数据类型 | 内容 | 存储方案 |
|----------|------|----------|
| 用户画像 | 基础信息、认知水平、薄弱环节、学习偏好 | PostgreSQL |
| 知识图谱 | 知识点节点+边关系（通用骨架+包内扩展） | Neo4j 图数据库 |
| 错题剧本库 | 错题记录+心理路径+修正方案 | PostgreSQL + JSON |
| 学习轨迹 | 每轮学习的行为日志 | 时序数据库（InfluxDB） |
| 系统配置 | 当前激活的配置包列表 | Redis 缓存 |

## 三、配置包标准结构

### 3.1 配置包定义

配置包（Subject Pack）是承载特定学科/考试所需全部内容的标准化容器。一个配置包 = 一个完整的学习与训练解决方案。

### 3.2 配置包标准架构

```
<SubjectPack>/
├── meta.json                    # 包元数据
├── syllabus/
│   └── syllabus.json           # 考纲结构化数据（Agent 1 产出）
├── knowledge/
│   ├── kb_vocab.json           # 知识条目库（Agent 2 产出）
│   ├── tags.json               # 本包专用标签体系
│   └── dependency_graph.json   # 知识点依赖关系图
├── capability/
│   ├── ability_list.json       # 能力清单（心法+手法）
│   ├── templates/
│   │   ├── answer_template_名词解释.json
│   │   ├── answer_template_论述.json
│   │   └── answer_template_译篆.json
│   └── examples/
│       ├── question_level1.json
│       ├── question_level2.json
│       └── question_level3.json
├── scripts/
│   ├── micro_dramas.json       # 微剧本集
│   └── error_scripts.json     # 错题剧本模板
├── prompts/
│   ├── agent2_override.json    # Agent 2 的包专属 Prompt 补丁
│   ├── agent4_override.json    # Agent 4 的包专属 Prompt 补丁
│   └── agent5_triggers.json   # Agent 5 的跨包联动触发条件
└── resources/
    ├── media/                  # 图片/音频/视频素材
    └── reference/             # 参考资料原文（如《说文》段注）
```

## 四、国美书法配置包详细设计

### 4.1 包元数据

| 字段 | 内容 |
|------|------|
| 包ID | `cafa_calligraphy_2026` |
| 目标考试 | 中国美术学院书法学本科专业校考（复试） |
| 适用方向 | 书法与篆刻 / 书法学与教育 |
| 考试时长 | 60 分钟 |
| 满分 | 100 分 |
| 配置包优先级 | ⭐⭐⭐⭐⭐（旗舰级首发包） |

### 4.2 知识库骨架（知识图谱主干）

#### 模块一：译篆与文字学

```
译篆与文字学
├── 《说文解字》基础
│   ├── 540部首（重点前100个）
│   ├── 六书理论（象形/指事/会意/形声/转注/假借）
│   └── 部首统属法（拆字→拼装）
├── 一简对多篆（高频易错）
│   ├── ⭐⭐⭐⭐⭐ 斗/鬥、发/髮/發、复/複/復、尘/塵
│   ├── ⭐⭐⭐⭐  云/雲、里/裏、余/餘、征/徵
│   └── ⭐⭐⭐  面/麵、须/須、采/採、冲/沖、历/曆/歷
└── 书体字形辨识
    ├── 草书释文（《书谱》、二王草书、汉简）
    ├── 篆书释文（石鼓文、说文小篆）
    └── 隶书释文（汉碑）
```

#### 模块二：古文标点与翻译

```
古文标点与翻译
├── 句读基础
│   ├── 句首标志词（夫、盖、故、是以）
│   ├── 句尾标志词（也、矣、焉、乎、哉）
│   └── 固定结构（者…也、若非…也、虽然…然）
├── 文本来源
```
