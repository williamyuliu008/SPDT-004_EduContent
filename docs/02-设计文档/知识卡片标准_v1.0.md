## 一、定位与适用范围

本标准是 SPDT-004 知识卡片体系的**统一Schema规范**，用于：

- 知识卡片的创建、校验、流转
- 不同领域工具（古史/书法/历史微剧本等）的互操作
- 向 Anki、闪卡App、ebook 等下游工具的输出
- 卡片包的版本管理与血缘溯源

**不适用范围**：电子书（由 ebook-builder 标准另行定义）、长篇剧本杀文本、纯娱乐内容。

## 二、卡片类型体系（四型）

| type 值 | 中文名 | 用途 | 是否进入轮转 |
|:---|:---|:---|:---|
| `node` | 节点卡 | 原子知识点，一事一卡 | ✅ 是 |
| `strategy_cause` | 原因分析卡 | 回答"为什么发生" | ✅ 是 |
| `strategy_impact` | 影响分析卡 | 回答"产生了什么后果" | ✅ 是 |
| `strategy_turning` | 转折分析卡 | 回答"关键转折点是什么" | ✅ 是 |
| `chain` | 链卡 | 逻辑链全景摘要（节点+策略卡聚合） | ❌ 仅展示 |

### 2.1 卡片类型说明

**node（节点卡）**：最小的知识原子。一个考点、一条史实、一个概念，front 是问题或关键词，back 是核心答案。不允许一个 node 同时包含两个独立知识点。

**strategy_cause / strategy_impact（分析卡）**：在链内提供因果分析视角。front 格式为 `[CHAIN_XXX] 标题\n问题`，back 包含分析逻辑和记忆口诀。strategy 类型通过 front 末尾的提问（`为什么？`/`产生了什么后果？`）与 node 区分。

**chain（链卡）**：同一逻辑链内所有 node 和 strategy 的聚合摘要。back 包含链类型（原因类/影响类/对比类）、关键节点列表、核心结论。chain 卡的 card_id 与 chain_id 相同。

## 三、Schema 必须字段

### 3.1 所有卡片必须包含

```json
{
  "card_id": "H_W4_世界近代_01_01",
  "type": "node",
  "chain_id": "CHAIN_世界近代_01",
  "front": "[CHAIN_世界近代_01] 帝国主义扩张矛盾",
  "back": "19世纪末，列强瓜分完毕殖民地市场……【★★★★★考点】",
  "source": "帝国的崩塌"
}
```

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `card_id` | string | 全局唯一标识符，见命名规范（第5节） |
| `type` | enum | `node` / `strategy_cause` / `strategy_impact` / `chain` |
| `chain_id` | string | 所属逻辑链ID，同链内节点共享 |
| `front` | string | 问题/标题。strategy 类型格式：`[CHAIN_XXX] 标题\n问题` |
| `back` | string | 答案/内容。含核心知识点和考点标记 |
| `source` | string | 内容来源，如剧集名/文档名/对话主题 |

### 3.2 包格式（cards.json）

```json
{
  "schema_version": "1.0",
  "pack_id": "古史_v4_全18链",
  "pack_title": "世界风云·一战与凡尔赛",
  "domain": "高考历史",
  "series": "古史系列第四卷",
  "total_cards": 133,
  "total_chains": 17,
  "generated_at": "2026-08-07T10:00:00",
  "generated_by": "古史_v4_卡片_自动生成器",
  "cards": []
}
```

包内所有卡片统一放在 `cards` 数组中，`type` 字段区分类型，不再拆分 `node_cards` / `strategy_cards` / `chain_cards` 三数组（v1-v3 历史数据迁移时合并）。

## 四、Schema 扩展字段（按场景选用）

### 4.1 考试/备考专用

```json
{
  "exam_type": "名词解释",
  "difficulty": "理解",
  "frequency": 5,
  "scoring_points": ["作者是许慎（东汉）", "以小篆为基准"],
  "common_mistakes": ["误写成《说文解字》是清代著作"],
  "answer_template": "名词解释_四句公式",
  "back_core": "东汉许慎著，首部系统分析汉字字形的字典，以小篆为基准，归纳六书"
}
```

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `exam_type` | string | 题型：名词解释/简答题/论述题/选择题 |
| `difficulty` | enum | `记忆` / `理解` / `应用` / `分析` |
| `frequency` | integer | 考频评分 1-5，**必须用数字，禁止用星星符号** |
| `scoring_points` | string[] | 采分点列表 |
| `common_mistakes` | string[] | 常见错误列表 |
| `answer_template` | string | 答题模板名称 |
| `back_core` | string | 精炼版 back，用于 Anki 等轻量展示；不超过 150 字 |

### 4.2 元数据

```json
{
  "domain": "高考历史",
  "ep": 1,
  "maturity": "RAW",
  "tags": ["#domain/高考历史", "#module/安史之乱", "#关联/颜真卿"],
  "created_at": 1699999999,
  "updated_at": 1699999999,
  "last_reviewed": 0
}
```

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `domain` | string | 领域标识，用于跨包流转时识别 |
| `ep` | integer | 所属剧集/章节编号 |
| `maturity` | enum | `RAW`（原始）/ `REVIEWED`（已审核）/ `VERIFIED`（已验证） |
| `tags` | string[] | 检索标签，见第6节标签规范 |
| `created_at` | unix timestamp | 创建时间 |
| `updated_at` | unix timestamp | 更新时间 |
| `last_reviewed` | unix timestamp | 最近复习时间（Anki 间隔复习用） |

### 4.3 血缘溯源（SPDT 护城河）

```json
{
  "source_conv_id": "conv_8f3a9c1",
  "extraction_tool": "autoclaw",
  "extraction_version": "0.9.1"
}
```

| 字段 | 说明 |
|:---|:---|
| `source_conv_id` | 原始对话/文档 ID，方便回溯 |
| `extraction_tool` | 提取工具名称 |
| `extraction_version` | 提取工具版本号 |

## 五、命名规范

### 5.1 card_id 命名规则

```
{域代码}_{版本号}_{链ID}_{序号}
```

| 组成部分 | 规则 | 举例 |
|:---|:---|:---|
| 域代码（1位） | H=历史 G=古史 C=书法 E=通用 | H |
| 版本号 | 自由文本，下划线连接 | W4 |
| 链ID | 中文/英文，保留原名 | 世界近代_01 |
| 序号 | 两位数字，不足补零 | 01 |

**示例：**
- `H_W4_世界近代_01_01` — 古史v4，世界近代第1链，第1张卡
- `CAFA_KB_CAFA_001` — CAFA书法包，CAFA链，第1张卡
- `E_GEN_译篆要诀_01` — 通用领域，译篆要诀链

### 5.2 chain_id 命名规则

```
CHAIN_{链ID}
```

链ID在包内唯一，如 `CHAIN_世界近代_01`、`CHAIN_CAFA_译篆要诀`。

### 5.3 pack_id 命名规则

```
{域}_{版本名}_{包类型}
```

示例：`古史_v4_全18链`、`cafa_calligraphy_2026`。

## 六、标签规范（TAG Specification）

### 6.1 设计原则

- **字段管元数据，标签管检索，两套严格分开，互不冗余**
- 同一个事实只存一个位置：既在结构字段里，又在标签里是冗余维护负担
- 标签用于：跨包检索、灵活分类、用户自定义扩展

### 6.2 命名空间前缀

| 前缀 | 用途 | 举例 |
|:---|:---|:---|
| `#domain/` | 大领域 | `#domain/高考历史` `#domain/书法校考` |
| `#subject/` | 学科 | `#subject/古代汉语` `#subject/世界史` |
| `#module/` | 模块/章节 | `#module/文字学` `#module/安史之乱` |
| `#关联/` | 关联考点 | `#关联/六书` `#关联/颜真卿` |
| `#source/` | 来源 | `#source/墨骨山河_ep01` |
| `#flag/` | 临时/特殊标记 | `#flag/待审核` `#flag/重要` |

### 6.3 标签体系与结构字段的关系

| 结构字段 | 标签对应 | 关系 |
|:---|:---|:---|
| `difficulty` | — | 纯字段，标签不同步 |
| `frequency` | — | 纯字段，存数字不用星星 |
| `exam_type` | `#exam_type/名词解释` | **字段+标签双重保留**，字段管逻辑，标签管检索 |
| `domain` | `#domain/高考历史` | **字段+标签双重保留** |
| 分类信息 | `#module/` `#关联/` | 仅标签，字段中无对应字段 |

**禁止**在标签中存储结构化数据（如 `#考频/⭐⭐⭐⭐⭐`），应使用数值字段。

## 七、长度门禁

### 7.1 back 长度限制

**核心原则：一个 back 最好能在手机屏内不滚屏读完。**

| 卡片类型 | back 上限 | back_core 上限 |
|:---|:---|:---|
| `node`（历史/通用） | **≤ 200 字** | ≤ 150 字 |
| `node`（考试/CAFA 书法） | **≤ 500 字** | ≤ 200 字 |
| `strategy_cause` / `strategy_impact` | **≤ 350 字** | ≤ 200 字 |
| `chain` | **≤ 600 字**（聚合摘要，可较长） | 不适用 |

> 注：字数统计不含 markdown 语法标记。
> 考试类 node 允许更长，原因是名词解释/简答等题型需要完整的核心要素列表。

### 7.2 超出限制的处理方式

**优先拆卡**：将长 back 的内容拆成多个 node，串回同一 chain。
**次选截断**：生成阶段对超长 back 生成 `back_core` 精炼版，完整内容移入 `back_detail`（非标准扩展字段），由展示层决定用哪个版本。

## 八、数据校验规则

### 8.1 生成器必须通过的校验

```python
#伪代码：卡片生成器内的校验
def validate_card(card):
    assert card["card_id"], "card_id 不能为空"
    assert card["type"] in {"node", "strategy_cause", "strategy_impact", "chain"}, "type 无效"
    assert card["chain_id"].startswith("CHAIN_"), "chain_id 必须以 CHAIN_ 开头"
    assert card["front"].strip(), "front 不能为空"
    assert card["back"].strip(), "back 不能为空"

    # 长度门禁
    back_len = len(card["back"])
    if card["type"] == "node" and back_len > 200:
        warn(f"node back 超过200字({back_len}字)，建议拆卡")
    if "strategy" in card["type"] and back_len > 350:
        warn(f"strategy back 超过350字({back_len}字)，建议拆卡")

    # frequency 必须是数字
    if "frequency" in card:
        assert isinstance(card["frequency"], int), "frequency 必须是整数"
        assert 1 <= card["frequency"] <= 5, "frequency 必须在1-5之间"

    # 标签格式
    if "tags" in card:
        for tag in card["tags"]:
            assert tag.startswith("#"), f"标签必须以#开头: {tag}"
```

### 8.2 标签白名单（可选扩展）

对于 `#domain/`、`#subject/`、`#module/` 等固定维度，建议维护一个白名单文件 `tags_whitelist.json`，生成时校验标签是否在白名单中，防止标签飘移。白名单在首次使用时生成，之后持续扩充。

## 九、历史数据迁移说明

v1-v3 卡片包（node_cards / strategy_cards / chain_cards 分数组结构）需合并为统一 `cards` 数组格式。

迁移脚本参考逻辑：
1. 读取原始 JSON，提取 `node_cards` / `strategy_cards` / `chain_cards`
2. 合并到 `cards` 数组，`type` 字段已在各子数组中体现
3. 补充缺失字段（`chain_id`、`source`），`maturity` 默认为 `RAW`
4. 输出迁移后格式，文件名加后缀 `_v1format`

## 十一、素材卡扩展模块（v1.1 增量）

> 来源：知识卡片双层架构共识（2026-08-07）
> 定位：本节为 v1.0 的增量扩展模块，与现有考试卡体系**并行共存**，不破坏已有卡片兼容性。

### 11.1 设计背景

现有标准以「考试卡」为主要设计对象，适用于 Anki 轮转和备考复习。但当卡片库需要支撑「写作输出」（专题报告、书籍章节、知识科普）时，考试卡的约束反而成为限制：

- back ≤ 200字的限制 → 叙事被打碎，无法直接用作写作素材
- 单链归属 → 同一知识点无法在不同写作上下文中复用
- back_core 是 Anki 精炼版 → 不是面向写作的"可展开素材"

**素材卡**是为「写作」场景设计的卡片变体，从同一个知识原子出发，但面向组合创作优化。

### 11.2 本征层与素材卡的关系

```
【本征层】—— 知识原子，不可变（v1.0 现有字段）
  card_id / 核心事实 / sources[] / concepts[] / version_history

      ↓ 从本征层派生，ai辅助创作

【素材卡】—— 写作场景专用变体（v1.1 新增）
  复用本征层的 card_id + sources + concepts
  新增 materials 层：narrative / data_points / quotes / argument_framings
  新增 multi_chains：多链归属（同一素材在不同上下文中复用）
```

> **重要原则**：素材卡不重复存储本征事实。所有事实性内容必须在本征层维护，素材卡只存储「面向写作的呈现方式」。

### 11.3 素材卡 Schema

素材卡有两种存在形态：

**形态A：在同一卡片JSON中内嵌 materials 层（推荐）**

```json
{
  "card_id": "H_W4_世界近代_01_01",
  "type": "node",
  "chain_id": "CHAIN_世界近代_01",
  "source": "帝国的崩塌",

  // v1.0 现有字段（考试用）
  "front": "帝国主义扩张矛盾",
  "back": "19世纪末，列强瓜分完毕殖民地市场……【★★★★★考点】",
  "back_core": "列强瓜分殖民地，市场矛盾激化",

  // v1.1 新增：素材层（写作用）
  "materials": {
    "narrative": "当欧洲列强在柏林会议上划完非洲的最后一条边界线时，他们不知道——自己亲手埋下了世界大战的导火索。瓜分完毕意味着扩张停止，而停止扩张意味着内部矛盾开始爆炸。",
    "data_points": [
      "1884-1885 柏林会议",
      "非洲90%领土被瓜分",
      "英德海军竞赛（1904-1912）",
      "1905年摩洛哥危机"
    ],
    "quotes": [
      "'太阳永不落下'——大英帝国殖民迷思的代价",
      "丘吉尔：'1914年的战争不是意外，是精心策划的政策'",
    ],
    "visual_prompt": "列强在瓜分非洲地图上画线的讽刺漫画，深色调，约1900年报纸插画风格",
    "argument_framings": {
      "经济视角": "殖民地市场饱和→资本输出受阻→贸易保护主义抬头→战争",
      "政治视角": "均势打破→同盟体系固化→局部冲突必然升级为全面战争",
      "社会视角": "民族主义情绪被殖民扩张喂养→各国民众被民族仇恨动员"
    }
  },

  // v1.1 新增：多链归属
  "chains": [
    "CHAIN_世界近代_01",
    "CHAIN_全球史_殖民体系"
  ],

  // v1.1 新增：输出标记
  "export_tags": ["适合_通俗历史读物", "适合_高中教材_帝国主义", "适合_视频脚本"]
}
```

**形态B：独立素材包（用于大型写作项目）**

当素材卡数量大、或需要独立版本管理时，可将 `materials` 层提取为独立 JSON，与本征卡通过 `card_id` 关联：

```
books/{book_id}/
  ├─ meta.yaml
  ├─ outline.md
  ├─ materials_index.json      ← 素材包索引
  └─ materials/
      ├─ H_W4_世界近代_01_01.json
      ├─ H_W4_世界近代_01_02.json
      └─ ...
```

```json
// materials_index.json
{
  "book_id": "一战与凡尔赛_专题报告",
  "card_id": "H_W4_世界近代_01_01",
  "origin_pack": "古史_v4_全18链",
  "adapted_for": "通俗历史读物_战争主题",
  "materials": { ... }
}
```

### 11.4 素材层字段说明

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `materials.narrative` | string | **叙事版back**：完整的故事化叙述，面向写作直接使用。字数不限，500-1500字为佳 |
| `materials.data_points` | string[] | 可引用的具体数据点：年份、数字、关键事实（用于报告/书籍中的论据） |
| `materials.quotes` | string[] | 名言/原文引用，含出处（用于报告中直接引用） |
| `materials.visual_prompt` | string | 图像生成提示词（用于配图/插画/视频封面） |
| `materials.argument_framings` | dict | **多视角论证框架**：同一事实的不同叙述切入角度，key=视角名，value=因果逻辑链 |
| `chains` | string[] | **多链归属**：该素材可归属的逻辑链列表（考试链+写作链并行） |
| `export_tags` | string[] | **输出标记**：该素材适合的输出场景，用于筛选 |

### 11.5 多链归属规则

```
rules:
  - 一张素材卡可归属于多条链（chains 数组）
  - chain_id 字段保留，作为"默认/主链"（考试场景使用）
  - chains 数组包含所有归属链（写作场景使用）
  - 不同链下，同一素材的呈现差异通过 materials.argument_framings 区分
  - chains 数组为空时，该卡为"纯考试卡"；有值时，该卡兼具素材属性
```

### 11.6 与考试卡的关系

| 维度 | 考试卡（v1.0） | 素材卡（v1.1） |
|:---|:---|:---|
| 核心目标 | 记忆与复习 | 组合与创作 |
| back 长度 | ≤ 200字 | 无硬限制，推荐 500-1500字 |
| 组织维度 | 单链归属（chain_id） | 多链归属（chains[]） |
| back 内容 | 问答式，精炼原子化 | 叙事式，保留完整逻辑 |
| materials 层 | 无 | 有（narrative/quotes/framings） |
| 适用输出 | Anki 轮转 | 书籍章节/专题报告/视频脚本/科普文章 |
| 与本征层关系 | 直接使用本征事实 | 从本征层派生，事实不可变 |

### 11.7 素材卡生成指南

**什么时候生成素材卡？**

- 卡片需要进入某个写作项目时
- 专题报告/书籍章节需要从卡片库筛选素材时
- 同一知识点需要在多个写作上下文中复用时

**生成方式：**

```python
#伪代码：素材卡生成流程
def generate_materials_card(card: dict, writing_context: str) -> dict:
    # 1. 复制本征层（card_id/sources/concepts 不变）
    materials_card = {
        "card_id": card["card_id"],
        "chains": [card["chain_id"]],  # 默认归属
        "materials": {}
    }

    # 2. 根据写作上下文，从本征事实生成 narrative
    materials_card["materials"]["narrative"] = llm_rewrite(
        base_facts = card["back_core"],
        style = "narrative",
        context = writing_context,  # "通俗历史读物" / "学术论文" / "视频脚本"
    )

    # 3. 提取可引用的 data_points
    materials_card["materials"]["data_points"] = extract_data_points(card["back"])

    # 4. 生成 argument_framings（多视角）
    materials_card["materials"]["argument_framings"] = {
        "经济视角": llm_generate(),
        "政治视角": llm_generate(),
        "社会视角": llm_generate(),
    }

    # 5. 添加 export_tags
    materials_card["export_tags"] = classify_for_output(card)

    return materials_card
```
