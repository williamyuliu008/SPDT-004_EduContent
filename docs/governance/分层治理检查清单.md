## 1. 用途

把"分层 + 窗口"翻译成**可执行的检查动作**——任何修改都必须经过这套清单。

---

## 2. 修改前检查（必做）

### 2.1 我要改的模块属于哪一层？

```
□ L0_stable       → 禁止在 W_high/W_mid 窗口改，只能在 W_low + 走 RFC
□ L1_evolutionary → 可以在 W_mid/W_low 改，但要走 PR 流程
□ L2_experimental → 可以在 W_high 改，但要走 PR + 写 _changelog.md
```

### 2.2 当前是哪个窗口？

```
□ W_low  稳定维护窗（1-2 周一次）→ L0 修复
□ W_mid  演化迭代窗（每天/每周）→ L1 内容生产
□ W_high 架构开发窗（每天多次）→ L2 新功能
```

> 如果不匹配：要么改窗口、要么改目标。

### 2.3 我有 RFC 吗？（L0 必走）

L0_stable 层任何修改必须先写 RFC，至少包含：
- [ ] 变更原因（P0 bug? 性能回归? 接口补全?）
- [ ] 影响范围（哪些模块会受影响）
- [ ] 回归测试计划
- [ ] 回滚方案

---

## 3. 修改中检查（必做）

### 3.1 跨层依赖检查

```
□ 我修改的是 L0，被 L1/L2 引用了吗？
  → 是：检查所有 L1/L2 引用点是否通过暴露的接口（__init__.py API）
  → 否：直接改

□ 我修改的是 L1，被 L2 引用了吗？
  → 是：保留 L2 已知接口，扩展而非破坏

□ 我修改的是 L2，被 L0/L1 引用了吗？
  → ❌ 禁止！L2 不应被 L0/L1 直接引用
  → 如果确实需要：先升级到 L1，再修改
```

### 3.2 文件位置检查

```
□ 修改 L0 文件 → 路径必须在 L0 范围内（1_ingest / knowledge_cards / quality / templates）
□ 修改 L1 文件 → 路径必须在 L1 范围内（2_structure 已产物 / 3_render / docs / autoclaw_kit）
□ 修改 L2 文件 → 路径必须在 L2 范围内（4_adapt / 古史_v4 / 墨骨山河 ep02-08 / 新功能）
```

### 3.3 接口契约检查

```
□ 是否修改了公开的 API（__init__.py 暴露的）？
  → 是：走 RFC + 主版本号升级
  → 否：自由改

□ 是否修改了配置文件（yaml/json）的 schema？
  → 是：检查所有引用方，更新 schema version
  → 否：自由改
```

---

## 4. 修改后检查（必做）

### 4.1 单元测试

```
□ L0 修改：跑全量单元测试 + 集成测试
□ L1 修改：跑增量单元测试 + 与 L0 接口对齐测试
□ L2 修改：跑 smoke test（仅验证能启动）
```

### 4.2 文档同步

```
□ SPDT.yaml 的相关 pdt 字段需要更新吗？
  → maturity / status / note / change_window

□ LAYERS.md 的模块清单需要更新吗？
  → 新增模块 / 模块升级 / 模块降级

□ ISOLATION.md（如果修改的是 L2）的已知缺陷需要更新吗？
  → 新发现的缺陷 / 已修复的缺陷

□ CHANGELOG.md（项目根）需要更新吗？
  → 任何 L0/L1 修改
```

### 4.3 Commit 信息

```
格式：<layer>/<type>(scope): subject

示例：
  L0/fix(ingest): 修复 M2 校准器对空 sources 的处理
  L1/feat(tools): 新增批量转换推送脚本
  L2/spike(4_adapt): 试验 Agent5 调度器
```

### 4.4 PR 模板填写（如果有 GitHub PR）

```
- [ ] Layer: L0 / L1 / L2
- [ ] Window: W_low / W_mid / W_high
- [ ] 关联 RFC: <链接 or "无">
- [ ] 测试: 通过 / 失败 / 跳过
- [ ] 文档同步: SPDT.yaml / LAYERS.md / ISOLATION.md / CHANGELOG.md
```

## 5. CI 自动化检查（建议实施）

### 5.1 layer_lint.py

自动扫描跨层违规：

```python
# 伪代码
for each .py file in repo:
    parse AST
    extract imports
    for each import:
        if imported_module.path starts with L0/ and current file is in L1/:
            assert import is from L0.__init__.py (公开 API)
        if imported_module.path starts with L0/ and current file is in L2/:
            assert import is from L0.__init__.py
        if imported_module.path starts with L1/ and current file is in L2/:
            assert import is from L1.__init__.py
        if current file is in L0/ and imported_module.path starts with L1/ or L2/:
            FAIL  # L0 禁止引用 L1/L2
```

### 5.2 window_check.sh

检查当前是否在匹配的窗口：

```bash
# 伪代码
CURRENT_WINDOW=$(get_current_window)  # 读取 git branch + 时间窗
CHANGED_LAYER=$(git diff --name-only | detect_layer)
if [ "$CURRENT_WINDOW" != "$CHANGED_LAYER.window" ]; then
    if [ "$CHANGED_LAYER" == "L0" ] && [ "$CURRENT_WINDOW" != "W_low" ]; then
        FAIL  # L0 改动不在 W_low
    fi
fi
```

### 5.3 layer_doc_sync.py

自动校验文档与代码一致性：

```
检查：
- SPDT.yaml 中每个 pdt 的 directory 是否存在
- 每个目录的 LAYER 标记是否在 SPDT.yaml 中
- ISOLATION.md（如果有）的文件清单是否与实际一致
```

## 6. Code Review 重点

### 6.1 L0 变更（最高优先级）
- [ ] RFC 完整
- [ ] 全量回归测试通过
- [ ] 至少 1 个 reviewer 拍板（willi）
- [ ] CHANGELOG 同步

### 6.2 L1 变更（中等优先级）
- [ ] 增量单元测试通过
- [ ] 与 L0 接口对齐
- [ ] MANIFEST.yaml / SPDT.yaml 同步

### 6.3 L2 变更（低优先级，鼓励试错）
- [ ] _changelog.md 记录
- [ ] smoke test 通过
- [ ] 失败案例标记 `STATUS: failed-archived`

---

## 7. 违规处理

### 7.1 等级 1：警告（自动恢复）
- 跨层 import 但通过公开 API
- L1 改动未在 W_mid
- 处理：自动警告，PR 可继续

### 7.2 等级 2：阻断（需修复）
- L0 改动未走 RFC
- L0 改动在 W_high/W_mid
- L0 import L1/L2 内部模块
- 处理：CI 红，必须修复

### 7.3 等级 3：事故（人工复盘）
- L0 改动导致生产事故
- L2 改动污染 L0/L1
- 处理：post-mortem + 流程改进

## 10. 速查表

### "我该改 L0，能改吗？"
```
能改的情况：
- 当前是 W_low 窗口
- 有 RFC（P0 修复 / 性能回归 / 联调测试）
- 走 PR 流程 + 至少 1 个 reviewer 拍板

不能改的情况：
- 当前是 W_high/W_mid
- 没有 RFC
- 想"顺手改一下"
```

### "我在 L2 加了个新模块，要更新什么？"
```
- SPDT.yaml：新增 pdt（layer_arch: L2_experimental）
- LAYERS.md：L2 表格加一行
- ISOLATION.md：如果是 _06_mvp_pipeline 子模块
- _changelog.md：写变更记录
- PR 模板：标 layer + window
```

### "我需要从 L2 升级到 L1，怎么做？"
```
参见 LAYERS.md §5
条件：
- ≥3 次成功生产/调用
- 接口契约冻结
- 单元测试覆盖 ≥70%
- 文档完整
- 至少 1 个 L1 模块消费它

动作：
- SPDT.yaml 改 layer_arch
- LAYERS.md 移到 L1 表格
- ISOLATION.md 删除或归档
- willi 拍板
```
