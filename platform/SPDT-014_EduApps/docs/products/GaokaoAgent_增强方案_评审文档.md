## A. AI 数学问答 Tab（新增）

### 特性描述

在现有 5 个 Tab（诊断/刷题/地图/面板/学科）基础上，新增第 6 个 Tab：**"AI答疑 🤖"**。

用户可以用自然语言输入高考数学问题（如"怎么判断奇函数还是偶函数？"），Agent 返回分步骤讲解、关联知识点卡片、同类例题推荐。

**关键交互：**

```
用户输入: "｜2x-1｜≤3 怎么解？"
    ↓
AI 上下文注入: 该生在"不等式"板块得分率 45% (来自最近诊断记录)
    ↓
Agent 回复 (三区布局):
  ┌─ 公式解法 ──────────────────────────┐
  │ Step 1: -3 ≤ 2x-1 ≤ 3             │
  │ Step 2: -2 ≤ 2x ≤ 4               │
  │ Step 3: -1 ≤ x ≤ 2                │
  ├─ 易错提示 ──────────────────────────┤
  │ ⚠ 你之前经常漏掉左边的负号         │
  │ 💡 记住口诀"去绝对值，左边加负号"    │
  ├─ 同类练习 ──────────────────────────┤
  │ [做一题] ｜x+3｜>5                  │
  └────────────────────────────────────┘
```

### 引入原因

1. **补全学习闭环的最大缺口：** 现有 5 个 Tab 覆盖了"诊断弱点→做题练习→查看地图→看面板数据"，但**缺少"遇到不会的题时即时求助"的场景**。这是学生学习中最自然的行为——碰到难题想问老师。
2. **差异化核心：** 鸿蒙应用商店中所有高考类 APP（作业帮/猿题库/高考直通车）的问答功能都是"拍照搜题→给答案"。GaokaoAgent 的差异化是**"不给答案，给讲解"**——AI 不直接告诉答案，而是拆解思路、指出易错点、推荐同类练习。这是智能体设计指南中的"个性化学习智能体"定位。
3. **数据飞轮：** 问答记录可反哺诊断模块——用户问过哪些知识点、哪些题型、理解程度如何，全部进入诊断数据。
4. **与小龙虾设计对齐：** 三区布局（问题区/解答区/关联区）+ 四色标记（蓝思考/绿正确/黄提示/红易错）+ 追问记忆。

## B. AI 自适应诊断

### 特性描述

增强现有的"诊断"模块——从"固定15题按序出题"升级为"AI根据答题表现动态选题"。

**当前逻辑：**
```
第1题(中等) → 第2题(中等) → ... → 第15题(中等) → 评分结束
```

**增强后逻辑：**
```
第1题(中等) 
  ├─ 答对 → 第2题升一级难度(较难)
  │         ├─ 答对 → 跳过同类题，进入下一板块
  │         └─ 答错 → 第3题降回中等确认
  ├─ 答错 → 第2题降一级难度(较易)
            ├─ 答对 → 第3题回到中等
            └─ 答错 → 标记此板块为薄弱，跳过后续同类题
动态8-12题完成 → 比固定15题更精准，更少
```

### 引入原因

1. **提效：** 学生时间宝贵。固定15题中有约30%是对学生已经掌握的内容的重复测试。
2. **更精准的诊断：** 自适应能更快定位"刚好不会"的边界（Vygotsky最近发展区），而不是把所有难度都测一遍。
3. **低成本实现：** 本质是前端选择逻辑的改变，不涉及 LLM 调用。判断规则简单（正确→升难度，错误→降难度+确认）。

### 修改范围

| 文件 | 操作 | 行数 | 说明 |
|:---|:---|:---|:---|
| `pages/Index.ets` | 修改 | +30 | `selectDiagAnswer()` 中增加自适应选题逻辑 |
| `mock/data.ts` | 修改 | +20 | 每道题增加 `prerequisite` 和 `nextUp` 字段 |

**总计: 修改 2 文件, 约 50 行变更。**

### 完全不依赖 LLM

纯前端规则引擎。题库数据加标签即可实现。

### 评审要点

- [ ] 自适应规则是否过于复杂？（当前设计：正确→升1级，错误→降1级+确认）
- [ ] 是否需要"跳过整个板块"的激进策略？
- [ ] 诊断结果是否需要与上次诊断做对比展示？

## C. AI 分步讲解

### 特性描述

增强现有的"刷题"模块——从"对/错 + 简单反馈"升级为"AI 逐步拆解+常见错误对比"。

**当前行为：**
```
学生提交答案 → 显示"正确！"或"错误，正确答案是 C"
```

**增强后行为：**
```
学生提交答案 →
  ├─ 答案正确 → 
  │   "解法正确！还有一种更巧妙的方法：利用对称性..."
  │   [再看一种解法] [下一题]
  │
  ├─ 答案错误 → 
  │   "你的答案: B, 正确答案: C"
  │   ┌── 你的思路可能卡在哪里 ──┐
  │   │ Step 2: 你假设了 f(x) 是   │
  │   │ 单调递增，但题目没有这个   │
  │   │ 条件。应该先求导判断单调性 │
  │   └──────────────────────────┘
  │   ┌── 正确解法 ──────────────┐
  │   │ Step 1: 求导 f'(x)=...    │
  │   │ Step 2: f'(x)<0 在 [0,π]   │
  │   │ Step 3: 所以选 C          │
  │   └──────────────────────────┘
  │   [做一道同类题巩固]
```

### 引入原因

1. **刷题≠学习：** 仅仅知道对/错不产生学习效果。认知科学表明反馈中的"错误原因解释"是学习效果最强的环节。
2. **模板成本低：** 分步讲解是结构化模板——题目→标准解→常见错误→容易卡住的步骤。本地规则可以覆盖 60%+ 题目。
3. **对接 LLM 后的潜力：** 如果学生追问"为什么这里要用求导？"，LLM 可以动态生成解释。

### 修改范围

| 文件 | 操作 | 行数 | 说明 |
|:---|:---|:---|:---|
| `pages/Index.ets` | 修改 | +40 | `submitTutor()` 后增加分步展示逻辑 |
| `components/AgentDiffCard.ets` | 复用 | 0 | 复用 A 特性中的对比卡片组件 |
| `mock/data.ts` | 修改 | +50 | 每道题增加 `errorAnalysis` 和 `stepByStep` 字段 |

**总计: 修改 2 文件, 约 90 行变更。**

### 70% 可用本地规则覆盖

常见的错误类型可以模板化（符号错误/公式记错/漏条件/概念混淆），LLM 只在本地规则无法匹配时才调用。

### 评审要点

- [ ] 分步讲解的粒度——每步多细？（太细拖沓，太粗没用）
- [ ] 是否允许学生追问"为什么"？
- [ ] 错误分析是否需要引用学生的具体输入？

## D. AI 学习洞察

### 特性描述

在现有"面板"Tab 底部新增一个"**📊 AI 学习洞察**"卡片（滑动到面板底可见）。

**内容模板：**
```
🔥 最大进步: 函数与导数 (上周55%→本周73%)
⚠ 最需关注: 解析几何 (连续3天未练习，当前正确率仅35%)
📋 AI建议: 
  1. 先10分钟快速复习 数列（基础扎实，过一遍即可）
  2. 主攻 解析几何 第3-5题（难度匹配你当前水平）
  3. 睡前2道 概率统计 保持手感
📈 趋势: 近7天刷题量下降20%，周末可以补回来
```

### 引入原因

1. **数据已经有，只是没展示：** 面板Tab已收集了大量学习数据（正确率/刷题量/板块得分），差一步"解读"。
2. **制造"被关心"的感觉：** 一个 AI 教练告诉你"你今天还没练解析几何"和冷冰冰的数据面板是完全不同的体验。
3. **纯计算零风险：** 不需要 LLM。所有洞察基于已收集的本地数据计算，规则透明可控。

### 修改范围

| 文件 | 操作 | 行数 | 说明 |
|:---|:---|:---|:---|
| `pages/Index.ets` | 修改 | +30 | `buildDashboard()` 底部增加洞察卡片 |
| `services/insight-engine.ts` | **新建** | ~50 | 基于历史数据计算洞察 |

**总计: 新建 1 文件, 修改 1 文件, 约 80 行。**

### 完全不依赖 LLM

纯本地数据计算。后续可升级为调用 LLM 生成更个性化的建议文案。

### 评审要点

- [ ] 洞察频率：每次打开面板时重新计算，还是缓存？
- [ ] "建议"是否该带有可操作的链接（如"点击开始解析几何练习"）？
