## 一、核心理念

**智能体的价值公式:**

```
价值 = 可访问的APP内部数据 × 可执行的APP内部操作 × 领域专有知识 × 跨端协同能力
```

通用大模型在这四个维度都是零。每一维度增加的不是"功能"，是一种新的能力维度。

## 三、各维度详解

### A. 长期记忆 — 智能体的根基

| 数据 | 来源 | 更新频率 | 用途 |
|:---|:---|:---|:---|
| 用户画像 | 首次使用时填写 + PC侧小龙虾定义 | 手动更新 | 个性化所有推荐和对话 |
| 学习历史 | 诊断+刷题模块自动记录 | 每次操作 | 薄弱点分析、难度匹配 |
| 统计数据 | 面板Tab实时计算 | 实时 | 趋势图、学习洞察 |

**关键认知:** 长期记忆不依赖 LLM。一个纯数据驱动的用户画像，比一个没有数据支撑的 LLM 对话更"智能"。

### B. 短期记忆 — 智能体的眼睛

| 数据 | 来源 | 生命周期 | 用途 |
|:---|:---|:---|:---|
| 当前页面 | `@State tab` 变量 | 会话内 | 过滤无关数据，聚焦当前上下文 |
| 操作序列 | 最近N个用户操作 | 会话内 | 推断意图（"连做3道解析几何→可能想专项训练"） |
| 意图推断 | B.1 + B.2 → 规则/LLM | 会话内 | 下次打开时预加载推荐内容 |

**关键认知:** "用户连续在刷题Tab做了3道解析几何"这个信息比"用户打开了APP"有价值100倍。

### C. 输入辅助 — 最被低估的维度

| 方式 | 实现 | 效果 |
|:---|:---|:---|
| 预填筛选条件 | 基于B.3意图推断→预选学科/难度 | 用户少点2-3次 |
| 推荐对话问题 | 基于A.2学习历史→生成3个"你可能想问" | 降低提问门槛 |
| 操作预测 | 做完一道题→直接出"再做一题"而不是返回 | 流畅度提升 |

**关键认知:** 用户打开APP不是为了聊天——是来做题、看结果、查弱点的。每减少一次手动输入，就是一次体验提升。

### D. 输出操作 — 智能体的手

| 层级 | 能力 | 示例 |
|:---|:---|:---|
| D1 展示内容 | 把分析结果展示给用户 | "你的解析几何薄弱，建议做这5题" |
| D2 推荐+可操作 | 展示推荐 + 一键执行按钮 | 推荐列表 + "开始练习"按钮 |
| D3 直接操作 | Agent直接修改APP状态 | 直接创建练习集→跳转到刷题Tab→开始计时 |
| D4 修改配置 | Agent修改APP设置 | 根据正确率自动调整难度偏好 |

**安全边界:** D3/D4 需要用户确认或设置中开启。删除/修改学习计划等危险操作必须经过确认弹窗。

### E. 内容管道 — 智能体的血液

```
PC侧小龙虾                    APP端
──────────                   ──────
整理知识点JSON         →      题库目录更新
批量生成考题            →      新增题目入库
格式化用户画像          →      长期记忆写入
AI工具链加工内容        →      APP内容源更新
导出APP学习数据         ←      供小龙虾全局分析
```

**关键设计:**
- 内容管道是单向或双向的、基于 JSON Schema 的标准化传输
- PC 侧做"重"的加工（批量生成考题、知识图谱整理）
- APP 侧做"轻"的消费（读取 JSON → 解析 → 入库）
- 不需要 APP 内实现复杂的编辑功能——那是 PC 侧的工作

### F. 自主规划 — 智能体的大脑

| 能力 | 依赖 | 成熟度 |
|:---|:---|:---|
| 学习路径规划 | A长期记忆 + D输出操作 | A/D 就绪后可建 |
| 出题策略 | A统计数据 + B意图推断 | A/B 就绪后可建 |
| 自适应调整 | A历史 + C输入辅助 + D输出 | A/C/D 就绪后可建 |
| 多算法协同 | 上述全部 | 远期 |

### G. 跨端协同 — 智能体的外部网络

```
PC侧 (小龙虾/管理工具)              APP侧 (GaokaoAgent)
──────────────────────              ────────────────────
知识库管理                           内容管道接收
  整理高考数学知识图谱     →SHARED_CTX→  解析JSON → 更新题库
                                    
题库批量生成                           内容管道接收
  LLM批量生成100道题       →SHARED_CTX→  验证格式 → 入库

用户画像输入                           长期记忆写入
  定义目标/薄弱点/偏好      →SHARED_CTX→  写入UserProfile

AI工具链加工                           内容管道接收
  OMAS DMC数据采集          →SHARED_CTX→  APP内容源更新
  OMAS CMC内容渲染          →SHARED_CTX→  考题/讲义格式化

APP数据导出                             数据导出
  学习数据/答题记录          ←SHARED_CTX←  供小龙虾全局分析
```

## 四、建设顺序（修订）

```
第一周 — 打地基 (无需LLM)
  ├─ A.长期记忆: 结构化UserProfile
  ├─ B.短期记忆: IntentContext (当前页+操作序列)
  └─ C.输入辅助: 基于意图的预填+推荐

第二周 — 能动手 (无需LLM)
  ├─ D1/D2输出: 学习洞察卡片 + 推荐练习按钮
  └─ D3输出: 推荐→直接创建练习集→开始做题

并行 — 建管道
  ├─ G.跨端: PC侧小龙虾↔APP的SHARED_CTX协议
  └─ E.内容管道: 知识库/题库 JSON Schema定义 + 首版导入

第三周+ — 聪明的 (需要LLM)
  ├─ B.3意图推断: LLM分析操作序列
  ├─ F.1学习路径: 基于A+B的LLM规划
  └─ D4修改配置: 用户确认后的自动调整
```

## 六、内容管道的实际设计

### PC侧 → APP侧 的数据流

```json
// 小龙虾侧产出: knowledge/math_algebra_v2.json
{
  "version": "2.0",
  "domain": "math",
  "board": "algebra",
  "nodes": [
    {
      "id": "alg_001",
      "name": "一元二次方程",
      "examFrequency": "high",
      "prerequisites": ["alg_000"],
      "questions": [
        {
          "id": "alg_001_q01",
          "text": "解方程: x² - 5x + 6 = 0",
          "options": ["x=2,3", "x=1,6", "x=-2,-3"],
          "answer": 0,
          "difficulty": 1,
          "stepByStep": "使用因式分解法...",
          "commonMistakes": ["符号错误", "漏解"]
        }
      ]
    }
  ]
}
```

### APP侧消费流程

```
APP启动时检查 content/manifest.json
  ├─ 有更新 → 下载新版本JSON
  ├─ 校验格式 → 解析
  └─ 替换旧版本 → 刷新题库
```

这个管道建立后，小龙虾侧可以批量生成题目、整理知识点、分析用户数据，APP 侧只需要做轻量消费。
