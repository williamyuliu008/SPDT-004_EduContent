## 第一部分：智能体APP架构深化

### 1.0 当前架构基线

我们已经建立了 8 维智能体框架 (A-H)，核心创新是**小龙虾统一API**——将PC作为所有APP的共同计算服务器。

```
┌──────────────────────────────────────────────────────────┐
│                    PC 侧 · 小龙虾                          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ LLM 引擎 │ │ RAG 知识库│ │ OMAS SDC │ │ Design SOP │  │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └──────┬─────┘  │
│       └─────────────┴────────────┴──────────────┘        │
│                          │                                │
│              小龙虾统一 API (localhost:8848)               │
│              /task  /knowledge  /content  /state           │
└──────────────────────────┬───────────────────────────────┘
                           │ HTTP/JSON
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
     gaokao-agent    thinkkit-coach    harmonycoder
     (出题/分析)      (学习计划)        (代码审查)
```

### 1.1 小龙虾统一API — 分阶段落地

#### Phase 1: 协议定义（7月第3周）
| 端点 | 职责 | 输入 | 输出 |
|:---|:---|:---|:---|
| `POST /task` | 通用任务调度 | app_id + task_type + payload + user_context | result + trace_id |
| `POST /knowledge/query` | 知识库查询 | app_id + domain + query | nodes[] |
| `POST /content/import` | 批量内容导入 | app_id + content_type + data[] | imported_count |
| `POST /state/write-back` | APP状态回写 | app_id + updates[] | acknowledged |

#### Phase 2: 小龙虾侧 mock → 真实后端（8月）
- 7月：mock 实现，验证接口协议
- 8月：接入 OMAS SDC（代码审查）+ Design SOP（设计生成）
- LLM就绪后：接入 LLM 引擎 → 真正的内容生成

#### Phase 3: 跨APP协同（9月+）
小龙虾可以感知多个APP的状态，实现跨APP智能：
- gaokao-agent 的错题 → thinkkit-flashcard 自动生成针对性闪卡
- rhythm-habit 的作息数据 → gaokao-agent 调整学习时段推荐
- harmonycoder 审查结果 → 反馈到 common/ 内核改进

### 1.2 GaokaoAgent 旗舰路径

GaokaoAgent 是智能体架构的旗舰验证项目，分三期推进：

```
v1.0-baseline (已推送)
  └─ 5-tab MVP: 面板/刷题/搜索/错题/设置
        │
        ▼
v2.1-foundation (7月) ── 8维地基，零LLM
  ├─ G: 小龙虾API规范
  ├─ A: UserProfile + error_attribution
  ├─ B: IntentContext + 跨会话书签
  ├─ C: 意图预填 + 冷启动引导
  └─ H: BatteryObserver
        │
        ▼
v2.1-hands (8月) ── 接入小龙虾，能动手
  ├─ D1/D2: 学习洞察卡片 + 推荐练习
  ├─ D风险矩阵 + 撤销机制
  ├─ E: 内容管道 JSON→APP 解析
  └─ G: POST /task 请求出题 + state 回写
        │
        ▼
v3.0-agent (LLM就绪后) ── 真正智能
  ├─ F: LLM学习路径规划
  ├─ B.3: LLM意图推断
  └─ D4: Agent自动修改配置
```

```
✔ CLI编译+签名+部署   build_any.py gaokao-agent --deploy  (15s 全自动)
```

### 2.1 自动化成熟度路线图

```
L0: 手工 (已超越)
  └─ DevEco Studio GUI 逐一点击

  └─ CLI单APP编译+部署 ✔  init-app模板生成 ✔

L4: 自治 (远期)
  └─ 市场反馈 → 自动需求 → 自动开发 → 自动发布
```
