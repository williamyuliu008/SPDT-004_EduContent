## 一、设计动机

### 1.1 为什么需要真题卡片？

- **现状**：v1.2.0 知识卡只有 1039 张**知识点卡**（历史 379 / 地理 294 / 政治 366）
- **缺口**：**没有"真题"卡**——真题是知识点的实战演练，是学生最需要的内容
- **数据**：`D:\9_archive\上海高考试卷\` 9 科 1990-2025 完整题库（地理/化学/生物/政治/数学/物理/英语/语文/历史）

### 1.2 真题 vs 知识卡

| 维度 | 知识卡（v1.2.0）| 真题卡（v1.0 草案）|
|:---|:---|:---|
| **目的** | 理解 1 个知识点 | 巩固 1 个知识点的实战 |
| **场景** | 碎片 5-15 分钟学习 | 考前 1 周循环练习 |
| **形式** | 因果链 5 层 + 助记 | 题干+选项+答案+解析+错因 |
| **关联** | K01-K07 chain | 真题 ↔ 知识卡 1:1 关联 |
| **数量** | 1039 张 | 50+ 套 × 30 题 = 1500+ 张 |

**关键设计**：**每张真题卡 ↔ 1 张主知识卡**（强关联，多形式强化同一考点）。

### 2.2 单张真题卡字段（v1.0 schema）

```json
{
  "card_id": "EXAM_2018_SH_HIST_30",
  "type": "exam",
  "schema_version": "1.0",
  "meta": {

  },
  "content": {

  },
  "links": {
    "knowledge_card": "K03_总理衙门设立",

    "stem_accuracy": 5,
    "explanation_quality": 5,
    "knowledge_link": 5
  }

```

### 2.3 字段说明（10 大字段）

| # | 字段 | 类型 | 说明 |
|:---:|:---|:---|:---|
| 1 | `card_id` | string | 唯一标识：EXAM_年份_省份_学科_题号 |
| 2 | `type` | string | 固定 "exam" |
| 3 | `schema_version` | string | "1.0" |
| 4 | `meta` | object | 元信息（年份/省份/学科/题号/分值/题型）|
| 5 | `content` | object | 题目内容（题干/选项/答案/解析）|
| 6 | `knowledge_chain` | object | 知识图谱关联（主卡/副卡/5 层/6 维）|
| 7 | `exam_meta` | object | 考试元信息（难度/技能/常见错）|
| 8 | `links` | object | 多形式链接（知识卡/电子书/视频/相关真题）|
| 9 | `created_at/updated_at` | date | 时间戳 |
| 10 | `auditor + audit_score` | object | 审核（教学专家+LLM）+ 5 维度评分 |

### 2.4 与 v1.2.0 知识卡的关系

```
v1.2.0 知识卡（K01-K07 chain）
    ↓ 关联（每张真题卡 ↔ 1 张主知识卡）
v1.0 真题卡（1500+ 张）
    ↓ 多形式链接
v0.3.8 电子书 7 章（深度）
v0.3.7 短视频（碎片）
v3.x 音频（通勤）
```

**关键设计**：
- **真题卡是"知识卡"的实战检验**（不是替代，是补充）
- **1 张知识卡可关联多张真题卡**（如 K03_总理衙门 → 3-5 张真题）
- **多形式链接**：1 张真题 → 1 张知识卡 + 1 章电子书 + 1 段视频 + 1 段音频

## 三、抽取流程

### 3.1 数据源

`D:\9_archive\上海高考试卷\` 9 科 1990-2025：
- 化学 1990-2025
- 历史 1990-2019 + 2024
- 地理 1990-2025（无 2023）
- 政治 1990-2018
- 数学 1990-2025
- 物理 1990-2025
- 生物 1990-2023
- 英语 1990-2025
- 语文 1990-2025

格式：doc / docx / pdf 混合

### 3.2 抽取工具链

| 工具 | 用途 | 状态 |
|:---|:---|:---|
| `pypdf` | PDF 文本提取 | ✅ 已装 |
| `python-docx` | docx 文本提取 | ✅ 已装 |
| `olefile` | doc 旧格式提取 | ❌ 未装（需 `pip install olefile` 或转 docx）|
| `libreoffice` 或 `pandoc` | doc → docx 批量转换 | ❌ 未装 |

**建议**：**先装 `olefile`**（轻量），或用 LibreOffice 批量转 doc → docx（功能强但重）。

### 3.3 抽取步骤（5 步）

```
Step 1: 文本提取
  PDF  → pypdf
  docx → python-docx
  doc  → olefile（或先转 docx）

Step 2: 题目分割
  按"选择题/材料题/简答题"分块
  按题号（如 1./2./3.）分割单题

Step 3: 字段提取（LLM 辅助）
  题干: 正则匹配（"1．" / "第1题"）
  选项: A./B./C./D. 分割
  答案: 关键词匹配（"答案：C" / "参考答案"）
  解析: 关键词匹配（"解析：" / "【详解】"）

Step 4: 知识点关联（LLM 自动 + 人工 review）
  输入: 题干+解析
  LLM 输出: knowledge_chain（主卡/副卡/5 层/6 维）
  人工 review: 抽样 10% 校对

Step 5: 卡片入库
  写 .json 到真题库/学科/年份.json
  生成 chain.json + main.json
  5 维度评分（CGM）
```

### 3.4 自动化与人工分工

| 维度 | 自动化（LLM/脚本）| 人工（教学专家）|
|:---|:---|:---|
| **文本提取** | ✅ 全自动（pypdf/docx/olefile）| ❌ 不需要 |
| **题目分割** | ✅ 全自动（正则）| ❌ 不需要 |
| **题干/选项/答案/解析提取** | ✅ 90% 自动 | ⚠️ 10% 校对 |
| **知识点关联** | ⚠️ 80% 自动（LLM）| ✅ 20% review |
| **常见错误（common_mistake）** | ❌ 难自动 | ✅ 教学专家写 |
| **5 维度评分（audit_score）** | ⚠️ 50% 自动 | ✅ 50% review |

**关键洞察**：**LLM 做批量提取，教学专家做"难的部分"（常见错因 + 评分）**。
