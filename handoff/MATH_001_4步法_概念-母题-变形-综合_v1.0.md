# 4 步法（概念-母题-变形-综合）知识卡规范 v1.0

> 立项目标：把 0905/0907 文档沉淀的"母题-变式"训练方法论结构化成可生产的"训练卡"产品形态，与 v1.2 真题卡并列。
> 适用版本：v1.0（首个发布版，覆盖前 3 步；第 4 步"综合"另设）
> 拍板：9-11 用户对齐会议（willi）

---

## 一、设计原则（与 0905/0907 一致）

1. **学科逻辑**：固定母题原型 → 可控变量变式 → 考点闭环覆盖
2. **训练逻辑**：正向训练（条件→方法→结论）vs 综合训练（条件隐藏/跨模块）
3. **产品逻辑**：3 个独立数据库（概念库/母题库/变形库），用 chain_id 串联

## 二、4 步法核心结构

```
第 1 步：概念（concept）            ← 知识体系地基
    ↓ 绑定
第 2 步：母题（parent_problem）    ← 训练核心单位
    ↓ 衍生 3-5
第 3 步：变形（variant）           ← 可控变式
    ↓
第 4 步：综合（composite）         ← 4 类构题法，**v1.0 不做**
```

**关键边界**：
- v1.0 范围：概念 + 母题 + 变形（前 3 步）
- v1.0 不做：综合卡（4 类构题法训练方法不同，需另设 v2.0 规范）
- 范围理由：前 3 步是"可控的正向训练"，可标准化生产；第 4 步"综合"涉及模块嫁接/条件隐藏，方法非结构化，v1.0 暂缓

## 四、3 类卡字段对照

| 字段 | 概念 | 母题 | 变形 |
|:---|:---|:---|:---|
| 核心标识 | id (concept_*) | id (pp_*) | id (var_*) + parent_id |
| 关联 chain | chain_id (1) | chain_id (1) | parent_id → chain_id |
| 涉及概念 | - | concepts_used (≥1) | concepts_used (≥1) |
| 难度/考频 | ✅ | ✅ | ✅ |
| 标题 | 定理/定义名 | 题核名 | 变形方向 |
| 核心内容 | 定义+符号+深度 | 题干+方法+步骤 | 变化+触发+首步提示 |
| 训练方式 | 填空/默写 | 完整做题 | 留白思考 |
| 评分要点 | - | 步骤分 | 触发+首步 |

## 五、4 步法与 v1.2 真题卡的关系

| 维度 | v1.2 真题卡 | 4 步法（v1.0） |
|:---|:---|:---|
| 抽象单位 | 考点（v1.2.0 chain） | 母题（底层方法） |
| 训练目标 | 应试刷题（题→考点→同类题） | 系统建构（概念→母题→变式） |
| 训练顺序 | 题→考点（归纳） | 概念→母题→变式（演绎） |
| 颗粒度 | 70 题/4 套 | ~130 母题 × 3-5 变式 = 500-650 题 |
| 适用人群 | 应试 | 系统建构 |
| 关联方式 | knowledge_link → chain | chain_id 直连 |
| **互补** | ✅ 同 chain 可双向 | ✅ 4 步法母题 → v1.2 真题 = 综合题 |

**关键洞察**：
- 4 步法母题 ≈ v1.2 真题卡的"考点"，但 4 步法更结构化（概念绑定+变式树）
- 4 步法变形 ≈ v1.2 真题卡的"同类题"，但 4 步法变式方向明确（4 类）
- 4 步法综合 ≈ v1.2 真题卡的"压轴题"，但训练方法不同（v1.0 不做）

## 六、生产流程（v1.0 范式）

```
LLM 起草（GLM-5）
  ↓
多 AI 交叉筛选（候选→精选）
  ↓
人工校验（保 2-3 道真题对应）
  ↓

  ↓
入库 knowledge_cards\数学\cards\
  ↓
GLM-5 审核（5 维评分 ≥ 4.0 验收）
```

**复用 v1.2 工具链**：

- 后台任务：阶段 1 升级 Start-Process + heartbeat（避免同步阻塞）
- 质量验收：5 维评分（概念清晰/方法正确/变式合理/可训练/可关联）
