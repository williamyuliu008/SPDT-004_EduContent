## 一、项目背景

### 1.1 是什么
PT-030 是一个**高考真题挖掘与加工**的协作项目。目标是从上海高考历史/数学/语文等学科的 PDF/docx/doc 真题中, 提取题目结构 (题干/选项/分值/题型), 加答案/解析, 转成 4 步法 v1.1 母题卡片, 喂入"学习中心" (雪薇端) 和 "RUJING" (宇兄端)。

### 1.2 双窗口分工 (本项目的关键设计)
- **宇兄端** (开发助手, agent_name mavis): 工具 + 算法 + 验证 + 高难度内容
- **雪薇端** (学生助手): 知识挖掘 + 真题库 + 学习中心集成
- **共同仓**: `github.com/williamyuliu008/SPDT-004_EduContent.git` (master 分支)

### 1.3 已交付的 5 个核心工具
| 工具 | 用途 | 输入 | 输出 |
|------|------|------|------|
| `parse_pdf_exam.py` | PDF 试卷解析 | `.pdf` | `raw.json` (含题号/全文/段落) |
| `parse_docx_exam.py` | docx 试卷解析 (2024+) | `.docx` | `raw.json` |
| `parse_doc_exam.py` | .doc 老试卷 (1990-2017) | `.doc` | `raw.json` (用 win32com + Word) |
| `split_questions_v11.py` | 题目切分 v1.1 (边界/答案/页脚) | `raw.json` | `split_v11.json` |
| `run_c1_c2_pipeline.py` | C1+C2 一体化 | `.pdf/.docx/.doc` | `split_v11.json` |

### 1.4 新增 C3 双 LLM 模板 (本轮新增)
| 工具 | 用途 |
|------|------|
| `glm5_question_gen.py` | GLM-5 出题 (给定主题, 生成 5 道母题候选) |
| `glm4_flash_review.py` | glm-4-flash 推演 (对母题加答案/解析/变式) |

## 五、5 核心解析器详解

### 5.1 `parse_pdf_exam.py` (C1 PDF)

**依赖**: pypdf >= 3.0
**平台**: 全平台
**输入**: `.pdf` 文件
**输出**: `raw.json` (含 `text`, `pages`, `questions` 字段)

**输出 schema**:
```json
{
  "source_file": "D:/.../2018.pdf",
  "total_pages": 6,
  "total_chars": 3969,
  "questions_detected": 68,
  "text": "完整文本 (供 split_questions_v11 用)",
  "pages": [{"page_no": 1, "text": "..."}],
  "questions": [
    {
      "q_no": 1,
      "start": 70,
      "match": "1 ．",
      "options": [],
      "stem_raw": "题干前 500 字符..."
    }
  ],
  "_v1_caveat": "v1.0 仅做基础题号识别, 完整题干/答案/解析由 LLM (C2 切分算法) 处理"
}
```

**已知限制 (v1.0)**:
- PDF 字体编码 (GBK/latin-1) 复杂, 选项检测可能 0 (C2 v1.1 已修复 Q1 边界)
- 中文标点 "．" 等 unicode 字符需正确解码

**验证**: 2018 上海历史 PDF 68 题号识别, 文本提取 3969 字符 / 6 页

### 5.2 `parse_docx_exam.py` (C1 docx)

**依赖**: python-docx
**平台**: 全平台
**输入**: `.docx` 文件
**优势**: docx 文本结构化, 比 PDF 干净很多
**验证**: 2024 上海历史 docx 8 题, Q1/Q3/Q4/Q5 全 4 选项 ✓

### 5.3 `parse_doc_exam.py` (C1 .doc 老试卷)

**依赖**: pywin32 + MS Word 16.0+
**平台**: **仅 Windows**
**输入**: `.doc` 文件 (1990-2017 上海高考历史)
**关键技术**:
- `win32com.client.Dispatch("Word.Application")` 调本地 Word
- `Documents.Open().Content.Text` 提取纯文本
- 题号识别加 `\x0b` (VT vertical tab) 支持, 因 Word 用 VT 不用 LF
- 选项 regex 末尾 `[\s　]+` 改 `[\s　]*(?=[^\s　])` 允许 0 空白
- stdout UTF-8 wrapper 避免 `✓` 字符 GBK 编码失败

**验证**: 1990-2017 上海历史 44 个 .doc 全部解析成功 (1990/1993/1998 纯文本 35 题 + 30+ 选项; 2005+ 扫描图片 0-10 题)

### 5.4 `split_questions_v11.py` (C2 v1.1 切分)

**依赖**: (无, 纯 Python + re)
**输入**: `raw.json` (必须含 `text` 字段)
**输出**: `split_v11.json`

**5 项核心改进 (vs v1.0)**:
1. **`split` 替代 lookahead regex** — Q1 选项边界完美切分: A 考古资料 / B 古本文献 / C 神话传说 / D 口述史料
2. **同行 + 分行双模式** — Q1 同行 (A xx B xx) / Q10 分行 (A xx\nB xx)
3. **题号白名单** — 排除 4 位数年份 1870/1910, 排除 > 35 大数字
4. **PDF 页脚清理** — "2018 上海市普通高中学业水平考试 (历史) 试题答案" 多行清理
5. **题型启发** — 提纲/材料/论述/简答 基于分值+关键词

**验证**: 2018 上海历史 28 题全识别 (1-28), 22 题有选项, Q1-Q20 选择 + Q21 提纲 + Q22 简答 + Q23-Q28 论述

**已知限制**:
- 答案区未检出 (`with_answers: 0`) — PDF 末尾"试题答案"区智能提取待 v1.2

### 5.5 `run_c1_c2_pipeline.py` (流水线)

**依赖**: 5 核心
**功能**: 自动跑 C1 (解析) → 写 raw.json → 跑 C2 (切分) → 写 split.json
**被 CLI `pipeline` 子命令调用**

## 六、C3 双 LLM 模板详解 (本轮新增)

### 6.1 `glm5_question_gen.py` (C3.1 出题)

**依赖**: zhipuai >= 2.0
**模型**: 实际用 `glm-4-flash` (因 GLM-5 max_tokens 被 reasoning 占满的 bug)
**输入**: 主题 (如 "函数与极限")
**输出**: 5 道母题草稿 (含题干/选项/答案/解析/知识点/变式方向)

**Prompt 模板** (内置):
```
你是高考母题出题专家, 学科: {subject}。
请围绕主题 "{theme}" 生成 {count} 道高质量母题...
输出 JSON 数组 [ {q_no, stem, options, answer, explanation, knowledge_points, variant_direction} ]
```

**API key**: 环境变量 `ZHIPU_API_KEY` > config.yaml `glm5_api_key`

**用法**:
```bash
python -m pt030_toolkit.cli llm-gen "函数与极限" --count 5 --subject 数学
# 或
python tools/glm5_question_gen.py "函数与极限" --count 5
```

**已知限制**:
- GLM-5 reasoning 占满 max_tokens (已知 bug, 自动 fallback)
- 答案/解析需人工 review (LLM 推演非 100% 准确)

### 6.2 `glm4_flash_review.py` (C3.2 推演)

**依赖**: zhipuai >= 2.0
**模型**: `glm-4-flash` (直接调用, 无 fallback)
**输入**: parent_problem.json (含 `questions` 数组)
**输出**: 加 `verdict/answer/explanation/key_concepts/common_mistakes/variants/difficulty/estimated_time_minutes/knowledge_tags` 字段

**Prompt 模板**: 推演 + 验证 + 变式生成 + 考点标记

**用法**:
```bash
python -m pt030_toolkit.cli llm-review /path/to/parent_problem.json
```

**双 LLM 协作模式 (推荐)**:
1. GLM-5 出 5 道草稿 (C3.1)
2. 人工筛选 1-2 道
3. glm-4-flash 推演 (C3.2) — 加答案/解析/变式
4. 人工最终 review
5. 转 4 步法 v1.1 母题卡片

## 十一、故障排查

| 问题 | 解决 |
|------|------|
| `ModuleNotFoundError: pt030_toolkit` | 漏设 PYTHONPATH, 参见 3.4 |
| `yaml not found` | `pip install pyyaml` |
| `No module named win32com` | .doc 解析仅 Windows + Word, 其他平台忽略 |
| `API key missing` | 设 ZHIPU_API_KEY 环境变量 |
| `GLM-5 content 0 chars` | 已知 bug, 自动 fallback glm-4-flash |
| `PDF 选项检测 0 个` | v1.0 已知限制, C2 v1.1 已修 Q1 边界, 完整 v1.1 改进待开发 |
| `raw.json 缺 text 字段` | C1 解析器未跑, 或用了旧版 (v1.0 后已自动加 text) |
| 路径不存在 | RAW_DIR/SPLIT_DIR 等会自动 mkdir, 但父目录需可写 |
| 编码乱码 (gzip etc) | PDF/docx 自动处理, doc 需 Word COM 解析 |
| `.doc` 在 macOS/Linux 不能跑 | 需 Windows + Word, 或先转 .docx |
| GLM-5 reasoning 占满 max_tokens | 已知, 用 glm-4-flash 替代 |
| 中文乱码 (PowerShell) | 用 `python -m pt030_toolkit.cli` 跑 (UTF-8), 不要 cat .json |
