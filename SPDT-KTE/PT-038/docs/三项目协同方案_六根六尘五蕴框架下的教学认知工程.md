# 三项目协同方案：六根六尘·五蕴框架下的教学认知工程

> **版本**：v1.0 | **日期**：2026-07-16 | **状态**：规划提案

---

## 一、背景：三位一体的认知传递闭环

当前存在三个独立跑通的项目，各自覆盖了教学认知工程的不同环节，但尚未形成数据层面的闭环协同：

| 项目 | 定位 | 已跑通的核心能力 |
|---|---|---|
| **PT-038 TextExperience** | 内容工厂（声尘+色尘发生器） | 微剧本生成、知识链卡片、电子书、广播剧音频 |
| **video_factory** | 视觉渲染工厂（色尘精加工） | 10种 Pillow 场景模板、TTS音频、MP4视频合成 |
| **rujing（HarmonyOS App）** | 移动交付层（认知落地终端） | 链阅读器、Flashcard 复习、音频播放、视频接口预留 |

教学建模文档的核心命题是：**用六根六尘（五尘/六尘外部传递）× 五蕴（内部认知链）× 脑科学约束（硬件规格）× 类比专属通道（高保真迁移），构建可计算、可验证、可规模化复制的教育设计协议。**

三个项目正好对应这个框架的三个功能层，但目前是"各自为战"——PT-038 生产的微剧本音频没有被 video_factory 消费，video_factory 生产的视频没有被 rujing 接入，类比通道、脑科学约束、五蕴诊断等机制尚未进入任何一方的工程规范。

## 二、框架映射：三项目与六根六尘·五蕴的对应关系

### 2.1 六根六尘 → 三项目的功能分工

```
                    ┌─────────────────────────────────────────┐
                    │         外部传递层（知识从哪里来）           │
                    └─────────────────────────────────────────┘

  声尘（听觉·主通道）  ─── PT-038 ──→  微剧本广播剧音频（primary）
  色尘（视觉·辅助）    ─── video_factory ──→ Pillow 渲染帧 + MP4 视频
  触尘（体感·补偿）   ─── PT-038剧本文字 ──→ 声尘触觉词汇描述
  身根/肢体尘        ─── 标注"暂缺"（大模型边界）

                    ┌─────────────────────────────────────────┐
                    │         内部认知层（知识到哪里去）           │
                    └─────────────────────────────────────────┘

  五蕴（色→受→想→行→识）─── rujing ──→  链阅读（色蕴）→ 卡片复习（行蕴）→ 识蕴落地
```

**关键映射**：

- **PT-038 是"六尘发生器"**：从 PT-037 知识库抽取结构化知识，生成微剧本（声尘原料）、电子书文本（色尘原料）、Flashcard（行蕴工具原料）。它承担的是"教师备课"的角色——把知识点拆成可传递的尘。
- **video_factory 是"色尘精加工"**：把 PT-038 的声尘原料（旁白文本）转化为 Pillow 渲染帧（静态视觉），再合成为 MP4 视频（动态色尘）。它承担的是"视觉锚点设计"的角色——把文本色尘变成可视觉编码的结构化图像。
- **rujing 是"认知落地终端"**：把 PT-038 的 Flashcard（行蕴工具）加载到手机端，通过间隔重复（spaced repetition）触发行蕴的主动检索回路；把 PT-038 的广播剧音频和 video_factory 的视频接入播放器，实现"随时随地"的学习场景。它承担的是"学习过程管理"的角色——把知识从"看过了"变成"记住了"。

### 2.2 五蕴 → 三项目的认知链覆盖

| 五蕴阶段 | 认知任务 | 当前覆盖项目 | 缺口分析 |
|---|---|---|---|
| **色蕴**（接收） | 感官接收外界信息 | PT-038（微剧本音频）+ video_factory（视觉帧） | 两者的语义对齐无显式标注 |
| **受蕴**（感受） | 即时情绪反应 | PT-038（核心问题驱动的认知冲突） | 情绪触发设计未工程化（无显式字段） |
| **想蕴**（分别） | 表象分别 + 意义初判 | PT-038（知识链 chain_id 结构化） | scene JSON 无 chain_id 关联 |
| **行蕴**（加工） | 主动检索的深加工 | rujing（Flashcard 间隔重复）+ PT-038（卡片设计） | 行蕴缺乏"输出-反馈"闭环的显式设计 |
| **识蕴**（内化） | 稳定内化的认知结果 | rujing（生/熟二态标记） | 无"识蕴是否真成"的验证机制 |

## 三、数据流设计：PT-038 → video_factory → rujing 闭环

### 3.1 完整数据流架构

```
PT-037 知识库（考点·能力·知识链）
         │
         ▼
┌─────────────────────────────┐
│  PT-038 TextExperience      │
│  微剧本 JSON + Flashcard    │  ← 当前状态：已跑通
│  广播剧 MP3 + 电子书         │
└─────────────────────────────┘
         │
         │  新增接口
         ▼
┌─────────────────────────────┐
│  video_factory              │
│  scene JSON × N            │  ← 当前状态：手工，已跑通10种模板
│  TTS 音频 + MP4 视频        │
└─────────────────────────────┘
         │
         │  新增接口
         ▼
┌─────────────────────────────┐
│  rujing HarmonyOS App       │  ← 当前状态：音频已接，视频接口预留
│  链阅读 + Flashcard + 视频  │  ← 视频播放能力待接入
└─────────────────────────────┘
```

### 3.2 关键数据接口定义

#### 接口 A：PT-038 → video_factory（场景 JSON 自动生成）

**输入**：PT-038 的 `micro_dramas.json` 中某集的四幕叙事文本
**输出**：video_factory 的 `scene_XX.json` 场景 JSON 数组
**规则**：

```json
// 场景 JSON 新增字段（v2 schema，兼容 v1）
{
  "scene_type": "timeline",
  "content": { ... },          // 原有 Pillow 渲染参数
  "page": { "start": 0.0, "duration": 0.0 },
  "scene_info": {
    "idx": 0, "total": 10, "name": "乾元元年·蒲州的墨与血", "dur": 0.0
  },
  // ===== 新增字段 =====
  "source_knowledge_nodes": ["书法/唐/颜真卿", "历史/唐/安史之乱"],
  "source_chain_id": "墨骨山河_ep01",
  "five_skandha": {
    "color_base": "本 scene 的色尘锚点（视觉关键词）",
    "sensation": "本 scene 触发的受蕴情绪类型：curiosity|resonance|solemnity",
    "discrimination": "本 scene 对应的想蕴分别点",
    "action_prompt": "本 scene 引导行蕴的输出任务（填空/判断/口述）",
    "recognition_marker": "本 scene 识蕴是否落成的检验关键词"
  },
  "analogy_block": {
    "applicable": true,
    "type": "II",
    "source_domain": "战场杀伐",
    "target_domain": "颜体书法的力量感",
    "mapping_table": [...],
    "difference_annotations": [...]
  },
  "semantic_alignment": {
    "audio_segment_ref": "FT001-NARR-03",
    "visual_element_ref": "CONTENT-ZONE-2",
    "alignment_note": "声尘讲'墨色焦渴如血痕'时，视觉区显示焦墨笔触特写"
  }
}
```

**转换器伪代码**（`PT038_to_VideoFactory.py`）：

```
输入：micro_dramas.json 的某一 episode 的四幕文本
步骤1：按叙事段落切分 scene（每段 → 一个 scene JSON）
步骤2：每段匹配到 10 种 Pillow 模板之一（基于内容类型：时间线→timeline，对比→contrast等）
步骤3：从 target_knowledge_nodes 提取 source_knowledge_nodes
步骤4：从核心问题提取 five_skandha.sensation（认知冲突类型）
步骤5：从 cross_pack_links 提取 analogy_block（如有）
步骤6：生成 scene JSON 数组 → 输出到 episodes/ep_XX/scenes/
```

#### 接口 B：video_factory → rujing（视频文件 + 元数据）

**输出文件**：

```
rujing_video_package_v1/
├── metadata.json              ← 视频包元数据
├── ep01_乾元元年.mp4         ← 视频文件
├── ep01_audio.wav            ← 纯净旁白音频（可选，用于后台播放）
└── ep01_scenes.json          ← 场景时间轴（用于进度同步）
```

**metadata.json 格式**：

```json
{
  "package_id": "墨骨山河_EP01",
  "total_episodes": 8,
  "episodes": [
    {
      "ep": 1,
      "title": "乾元元年·蒲州的墨与血",
      "subtitle": "颜真卿与安史之乱",
      "video_file": "ep01_乾元元年.mp4",
      "audio_file": "ep01_audio.wav",
      "duration_seconds": 216.0,
      "chains": ["墨骨山河_ep01_主链"],
      "cards": ["墨骨山河_EP01_card_01.json"],
      "scene_timeline": [
        { "idx": 0, "time": 0.0, "scene_name": "卷首标题", "chain_ref": null },
        { "idx": 1, "time": 6.3, "scene_name": "乾元元年蒲州", "chain_ref": "CHAIN_颜真卿_生平" },
        ...
      ]
    }
  ]
}
```

#### 接口 C：rujing → PT-038（学习行为反馈）

**数据流**：rujing 记录每张卡片的复习间隔、正确率、识蕴落成时间 → 反馈到 PT-038 的知识链标注系统

```json
{
  "feedback": {
    "card_id": "墨骨山河_EP01_C001",
    "recognition_time": 1689568800,
    "review_count": 3,
    "avg_interval_days": 1.5,
    "recognition_stable": true,   // 连续3次正确 → 识蕴落成
    "bottleneck_node": "安史之乱时间"  // 多次错 → 行蕴卡点
  }
}
```

这条数据反馈到 PT-038，可以驱动"五蕴卡点自适应"机制：自动识别哪些知识点是学生的行蕴卡点，优先在后续视频中增加相关 scene。

## 四、认知工程升级：四类新增机制

### 4.1 机制一：类比专属通道（Knowledge Type I/II 分类）

**依据**：教学建模文档§12-13 的知识分类框架

| 知识类型 | 特征 | 场景模板 | 类比处理 |
|---|---|---|---|
| **I型**（结构清晰，有日常同构体） | 译篆、书法技法 | `analogy_scene` | 主力类比 + 结构映射图 |
| **II型**（部分清晰，含领域假设） | 书法审美、书论概念 | `analogy_scene` | 受限类比 + 差异红框 |
| **III型**（纯形式化，无日常同构） | 古汉语语法结构、句读 | `steps_scene` | 纯结构色尘 + 行蕴推导 |
| **IV型**（具象事实性） | 朝代、年号、作者 | `timeline_scene` | 色尘时间轴，无需类比 |

**工程化**：在 PT-038 的 `meta.json` 中增加 `knowledge_type` 字段，video_factory 的 `scene_input_schema.json` 中增加 `analogy_block` 字段（见 3.2 接口 A 示例）。

**案例**：墨骨山河 Ep01 的"篆籀气"讲解属于 II 型知识
- 源域：战场杀伐的刀痕（学生可感的视觉记忆）
- 目标域：颜真卿笔法的力量感
- 映射：刀痕的"力量感" → 颜体的"筋骨之力"
- 差异标注：刀痕是金属划过，笔锋是毛笔弹性；刀痕是破坏性的，笔锋是建构性的

### 4.2 机制二：五蕴链的显式字段设计

**依据**：教学建模文档§7 的五蕴微流程

每个 scene JSON 增加 `five_skandha` 字段（见 3.2 接口 A），使五蕴认知链从"隐含设计直觉"变为"显式可校验的数据"：

- `color_base`：本 scene 的视觉锚点 → 对应色蕴
- `sensation`：触发的情绪类型（curiosity/resonance/solemnity）→ 对应受蕴
- `discrimination`：想蕴的分别点 → 提示后续行蕴的关联方向
- `action_prompt`：行蕴的输出任务 → 嵌入 Flashcard 或视频内互动
- `recognition_marker`：识蕴落成的检验关键词 → Flashcard 熟卡判断依据

**验收标准**：PT-038 生成的每个 micro-drama scene 必须包含完整的 `five_skandha` 字段，video_factory 渲染时校验字段完整性。

### 4.3 机制三：双重编码的语义对齐约束

**依据**：教学建模文档§11 的双重编码理论

声尘（PT-038 旁白）与色尘（video_factory 视觉帧）必须语义对齐，禁止"声尘讲 A、色尘放无关 B 图"。

**工程化**：在 scene JSON 的 `semantic_alignment` 字段中显式标注每段旁白与视觉帧的对齐关系（见 3.2 接口 A 示例）。

**校验规则**：scene_renderer 在生成帧时，自动检查 `semantic_alignment.audio_segment_ref` 与 `semantic_alignment.visual_element_ref` 的配对完整性；缺失则警告。

### 4.4 机制四：工作记忆容量约束

**依据**：教学建模文档§11 的工作记忆 4±1 组块约束

- 单个 scene 的视觉新要点 ≤ 4 个
- 单段旁白连续新信息 ≤ 3 个认知组块
- 超出则强制拆分 scene

**工程化**：在 `scene_input_schema.json` 中增加 `cognitive_load` 字段（`points_count: int`），`compose_video.py` 渲染前校验，超载则自动拆分或报警。

## 七、立即可做的第一步

**不需要等待 Phase B / Phase C，立即可以做的是**：

### 第一步：写 `PT038_to_VideoFactory.py` 转换器

**输入**：`配置包_cafa_calligraphy_2026/scripts/墨骨山河_ep01_颜真卿.json`（或 `micro_dramas.json` 中对应条目）
**输出**：`video_factory/episodes/墨骨山河_ep01/scenes/scene_XX.json` 数组

**转换逻辑**：

1. 读取 `墨骨山河_ep01_颜真卿.json` 的 `dramatic_roles` + `target_knowledge_nodes` + `cross_pack_links`
2. 按叙事段落切分四幕文本，每段生成一个 scene
3. 根据内容类型匹配 Pillow 模板：
   - 含时间/朝代/年号 → `timeline_scene`
   - 含人物对比/书法风格对比 → `contrast_scene`
   - 含技法步骤/书论概念 → `steps_scene`
   - 含核心问题/情感高潮 → `quote_highlight_scene`（新 analogy_scene 前身）
   - 无明确类型 → `dual_track_scene`（标签+说明双栏）
4. 生成 scene JSON v2（含 `source_knowledge_nodes` 字段）
5. 触发 video_factory 渲染管线 → TTS → compose → MP4

**验证数据**：`墨骨山河_ep01_颜真卿.json` 已有 349 行，包含完整的目标知识节点、人物角色、交叉链接——可以直接作为第一个测试用例。

## 八、风险与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| PT-038 微剧本是纯文本叙事，不是"知识点分镜" | 转换为 scene JSON 需要 AI 判断"哪段文字对应哪个视觉模板" | 先做人工映射验证，积累足够样本后训练转换 Prompt |
| video_factory 当前 scene JSON 无 chain_id 关联 | Flashcard 和 scene 之间无法建立知识链追踪 | 在 scene JSON v2 中增加 `source_chain_id` 字段，一步到位 |
| rujing 视频播放性能待验证 | 手机端 MP4 解码可能卡顿 | 先做 480p 低码率测试包，再逐步提升 |
| 三项目跨仓库，版本同步复杂 | 一方改动破坏另一方接口 | 定义 immutable 接口协议（metadata 格式冻结），各项目独立迭代 |
